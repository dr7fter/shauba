## 草稿图片

默认位置 `E:\刷吧\photo`。用户未单独提供草稿图时，**按题目顺序读取该目录中的图片**；
目录不存在或图片数量不足时，**只批改实际收到且能对应的题目，不得猜测缺失草稿**。
**回传时把每题的草稿路径填进 `draftPaths`**——App 不经手图片，只存路径与展示，
学员才能当场核对你的转述有没有写错。

## 五条核心原则

### 1. LaTeX 规范（极其重要）

`summary` / `earliestError` / `advice` / `betterSolution` 及所有分析文本中，
**所有数学符号、变量、公式、计算式、递推式、极限、矩阵**必须用 `$...$`（行内）
或 `$$...$$`（块级）包裹。

- 禁裸文本数学式：禁 `x^2`、`int 0 to pi`
- 必须写 `$x^2$`、`$\int_0^\pi$`
- JSON 字符串中反斜杠是合法单个 LaTeX 反斜杠（`\frac`、`\sin`、`\int`）

### 2. 深度步骤与断点定位

结合草稿图逐行核对推理，定位**最早错误断点**（精确到行号与具体公式），
而非只判最终答案。三类病因的判据与 verdict 对应关系见 `09` 第二节。

`errorTags` **只放 1 个主标签**（取该题最早断点所属类），其余病因放 `secondaryTags`。
归一函数按 aiming→concept→tactics 顺序**首个命中**，多标签会把「概念盲区 + 计算笔误」
判成瞄准失误，而病因聚类**直接决定明天推什么题**。

⚠️ **计算/符号类错误一律打 🔴 瞄准失误，不要自造「符号抄错」之类标签**——
后端归一函数只认「瞄准 / 计算 / 笔误」等词，自造标签会落入 `mixed` 兜底类，
病因聚类就统计不到（映射扩充见计划书 WP5）。

`partial` / `incorrect` 必须回填 `stepScore`（有效步骤分 0–100），口径见 `09` 第二节。
报告把它显示出来——学员看得见"自己错得多可惜"，`partial` 才不会退化成"又一个错"。

### 3. HLTV Rating（0.00–2.50）

数值锚点与硬约束见 `09` 第三节。批改侧只记两条纪律：

- **严禁打中庸安全分**，整组题必须按草稿实际优劣拉开梯度；
- 你给的是**证据分**，最终结算由内核合成（`.agent/03`），不要自己叠加惩罚。

### 4. 考场极速秒杀思路（betterSolution）

**严禁搬教科书式繁琐长证明。** 必须提供待定系数法、二重积分交换次序、
King 变换、特征多项式秒杀等极简技巧。当前解法已足够精炼则填 `null`。

**分工（2026-09-04 起）**：`betterSolution` 只负责**考场提速**那一下，
不承担标准详解——详解需求由用户在报告点「复制追问上下文」获得（考纲内完整推导，见配套节）。

### 5. 可执行修复动作（advice）

一条精准、直接、**明天即可落地**的刻意练习动作。

### 6. 断点诊断块（diagnosis，2026-09-03 新增）

`advice` 是一句话动作；`diagnosis` 是**同一件事的完整证据链**，
直接喂报告动线六段（我的入口 → 断点 → 为什么是死路 → 识别规则 → 正确入口 → 明日动作）。
字段定义与填写规矩见 `01-回传格式.md` 第 5 节，这里只讲**批改侧怎么写才不变味**。

| 字段 | 常见写坏的样子 | 该写成 |
|---|---|---|
| `myEntry` | 复述题干：「题目要求证明中值定理」 | 写动作：「看到『可导』就对等式两边求导」 |
| `whyDeadEnd` | 步骤流水账：「第一步错，第二步也错」 | 讲原理：「$f'(\xi)=2\xi$ 只在一个点成立，铺到全区间辅助函数就构造错了」 |
| `rule.negation` | 正面描述：「要注意 $\xi$ 的存在性」 | 否定在前：「禁止把待证式里的 $\xi$ 改写成 $x$ 当已知条件用」 |
| `fork.myPath` | 只写正确解法的反面 | 写学员**实际**走的那条，哪怕很短 |
| `acceptance` | 模糊：「要掌握好」 | 可当场判真假：「不看解法独立重做，用时 < 3:45 且辅助函数构造正确」 |

**severity 定级**（与画像 Level 1/2/3 对齐）：

| 级别 | 判定 |
|---|---|
| `L1` 致命 | 概念性错误，入口就错，自己看不出 |
| `L2` 战术 | 方法绕路 / 路径歧路，能做对但绕远或超时 |
| `L3` 精度 | 计算笔误、符号抄错，思路对 |

**errorCode 纪律**：只在 `characteristic.md` 里确实有编号时回填；
同一入口导致的题填同一个 code（这是「复发」统计的唯一依据）；
**没有编号就填 `null`，严禁临场造号**——未编码是合法状态，报告会显示「未编码」并提示补。

⚠️ **分配新编号前必须查重**（2026-09-03 事故）：09-03 新入库的「几何概型补集做差遗漏」
直接沿用了 09-02 已占用的 `E-037`（二次型特征向量回代校验），两个不同断点撞号，
会让报告的「复发」统计把两条互不相干的断点算成同一条。

```bash
grep -oE "\[E-[0-9]{3}\]" characteristic.md | sort -u | tail -5   # 先看已用到几号
grep -oE "\[E-[0-9]{3}\]" characteristic.md | sort | uniq -d      # 再查有没有撞号（应为空）
```

入库动作三件套：画像里加 `[E-0NN]` 条目 → 断点抽检表加一行（首次暴露 / 下次抽检）→
`characteristic-core.md` 摘要同步。三处缺一处，后续推题就查不到。

### evidence 会被原样上架（2026-09-04）

提示词写了「严禁无证据给分」，但过去报告从不显示证据，等于没人能查 AI 有没有编分。
现在报告会把**极差最大的那一维连同它的 `evidence` 原句**一起呈现（复盘屏
「这次评分的证据」段）。所以：写不出具体推导行的维度，就老老实实给 `score: null`。

### `correct` 题填固化卡，不再整块 null

`verdict = correct` → `diagnosis` 填三字段：`myEntry` + `rule.positive` + `whyItWorked`。
画像契约要的「连续 2 次独立避坑 → 🟢 已固化」**需要的正是做对题的证据**；
此前 correct 题 diagnosis 为 null，App 侧 `deriveFixState` 只能永远不给「已固化」。

### 固化状态由 App 判，批改侧不得自报

报告的固化态（首次暴露 / 观察中 / 已固化 / 待验证）由 App 用 `attempts` 序列计算
（`reportViewModel::deriveConsolidation` / `deriveFixState`）。批改提示词已删掉
「升级已固化」那句授权——凭一次做对就写「已固化」违反 `.agent/08` 三不伪造。
你在画像里同样只标 `[🟡 观察中]`，只有能指出**连续 2 次独立避坑的具体证据行**时才可升 `[🟢]`。

## ⚠️ 修法由批改标签决定，不要沿用上一轮自己的推断

**8/30→8/31 的教训**：我把 #143/#147 判为「见过不敢调用」（结论：讲一遍没用），
但 codex 批改标签是**「概念盲区」= 知识缺口**，讲一遍**有**用。
诊断口径错了，修法就全错。

三种「做不对」对应三种修法：

| 类型 | 表现 | 修法 |
|---|---|---|
| **知识缺口** | 不记得公式/定理 | 讲一遍 |
| **见过不敢用** | 记得但不确定能不能主动调 | 逼着调用（讲一遍**没用**） |
| **错误路径自动化** ⚠️ | 复习时**错得比第一次还快** | 入口处用**否定式**规则拦截旧路径 |

**错误路径自动化的识别信号**：复习耗时**低于**首次耗时，且结果照错
（`#7076` 115s→53s、`#10590` 677s→57s 仍 wrong）。
它伪装成「我会做」，最危险。

**修补规则必须用否定式**：「看到 X 应该做 Y」会被旧习惯覆盖；
「看到 X **禁止**做 Z」才能拦住。

## ⭐ 字段长度硬约束（2026-09-03 新增，报告可读性的源头）

**再干净的 UI 也救不了冗长的输出。** 批改报告一屏要装下 8 题 + 断点 + 审计，
所以每个字段都有长度上限。**超限即视为批改不合格，必须重写。**

| 字段 | 上限 | 要求 | 报告中的落位 |
|---|---|---|---|
| `summary` | **40 字** | 一句话点明性质，不复述题目 | 右栏「旁注」引文 |
| `earliestError` | **100 字** | 只定位最早断点 + 说清为什么错在此处；**禁止**顺手把正确解法也写完 | 中栏朱批卡（核心，唯一默认展开的长文本） |
| `betterSolution` | **150 字** | 只给关键技巧与结论，**严禁**完整推导 | 折叠区「标准解法」 |
| `advice` | **50 字** | 一个明天可落地的动作，含可背诵的识别规则 | 折叠区「明日动作」 |
| `errorTags` | ≤ 3 个 | 只用 🔴🟡🔵 三类战术标签 | 右栏标签行 |

**写作纪律**：

1. `earliestError` 与 `betterSolution` **不得重复**——前者说「我错在哪」，后者说「正解是什么」。
   两个字段讲同一件事是报告里最常见的冗余来源。
2. 已判定 `correct` 的题，`betterSolution` 填 `null`，不要为了填满而给一个更慢的解法。
   唯一例外：`methodSoundness: "detour"` 的绕路题，`betterSolution` 给省时版（见下文）。
3. 识别规则一律用**否定式**写：`看到 X 禁止做 Z`，而不是 `看到 X 应该做 Y`（见上文修法表）。

### `methodSoundness`：对题的含水量检测（2026-09-04 新增）

`verdict: "correct"` 的题默认填 `null`（即 `sound`，干净利落）。但两类「假会」必须标出——
它们是对题里最大的金矿，学员自己绝不会上报：

| 值 | 判定 | 配套动作 |
|---|---|---|
| `lucky` | 特殊值代入、代选项、直觉跳步——结果对但方法**不可复现** | `summary` 一句话点破不可复现性（如「走的是特殊值代入，变体会翻车」），`betterSolution` 给正解路径 |
| `detour` | 方法对但严重绕路（speed ≤ 60 / 用时 ≥ 1.6× 基准） | `betterSolution` 给**省时版**（上面纪律 2 的唯一例外） |

- **只在 `verdict: "correct"` 时填**；partial/incorrect 一律 `null`（方法已失败，谈不上可靠性）
- 拿不准就不填——`lucky` 误标比漏标更伤信任（学员会以为老师在挑刺）
- 后端 `normalize_method_soundness` 词表外丢弃，只认 `sound/lucky/detour`

### 整组摘要 `batch.summary` 三段式（2026-09-04 新增）

整组批改的 `summary` 是报告顶部「总诊断」的唯一文字来源，按三行写，**不超过 90 字**：

1. **分布**：N 题对 X 错 Y（Z 题超时严重 / 速度达标）
2. **聚类**：错题按 `errorCode` 归并——`E-027` 复发 2 次 / 各错各的（无聚类时直说）
3. **一件事**：📌 本次只带走一件：`<该聚类的否定式规则原文>`；无聚类则取 severity 最高题的规则

贪多是批改失效的头号原因——整组摘要只强调一件事，其余留给逐题字段。

### 配套：报告里的「复制追问上下文」（2026-09-04 改版，以此为准）

App 报告一键复制打包「题面 + 考纲详解要求 +（分割线后）我的断点过程」，
贴给新 AI 的目的是：**先独立拿到数一考纲内的标准详解**（步骤完整可上答卷、
关键步骤注明定理/公式依据、禁二级结论与秒杀技巧、特殊值凑答案），
且**不被先前批改思路带偏**——我的入口/断点放在分割线后，AI 解完再对照指出换路点。

对你（批改侧）的写作影响：

1. **`betterSolution` 不进复制模板**——它只留在报告「选填速算」区；
   写成自足结论的要求不变（禁「如前所述」「同上」）。
2. **标准详解不由 `betterSolution` 承担**——它只负责考场提速那一下；
   详解需求由用户点「复制追问上下文」获得。
3. `diagnosis` 各字段会整包进入复制文本（分割线后），照旧写学员实际路径、
   禁止依赖对话上下文。

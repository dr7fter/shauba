## 五条核心原则

### 1. LaTeX 规范（极其重要）

`summary` / `earliestError` / `advice` / `betterSolution` 及所有分析文本中，
**所有数学符号、变量、公式、计算式、递推式、极限、矩阵**必须用 `$...$`（行内）
或 `$$...$$`（块级）包裹。

- 禁裸文本数学式：禁 `x^2`、`int 0 to pi`
- 必须写 `$x^2$`、`$\int_0^\pi$`
- JSON 字符串中反斜杠是合法单个 LaTeX 反斜杠（`\frac`、`\sin`、`\int`）

### 2. 深度步骤与断点定位

结合草稿图逐行核对推理，定位**最早错误断点**（精确到行号与具体公式），
而非只判最终答案。

`errorTags` 三类战术标签：

| 标签 | 含义 | 判据 |
|---|---|---|
| 🔴 **瞄准失误** | 计算笔误 / 符号写反 | 思路完全正确，在通分/变上限求导/矩阵变换处算错 → verdict `partial`，保留步骤分 |
| 🟡 **概念盲区** | 定理前提遗漏 / 混淆边界 | 未验证极限存在拆分、连续可导混淆 → verdict `incorrect` |
| 🔵 **战术绕路** | 方法机械蛮干 / 超时严重 | 硬算超时，指出计算黑洞 → `speed ≤ 60` |

无法确定时明确用 `uncertain`，**不要猜测步骤或知识点**。

### 3. HLTV Rating（0.00–2.50）

综合实际耗时与基准时间（单选 3 分 / 多选 4 分 / 填空 5 分 / 解答 10 分）评估流畅度与经济效率。

| rating | 含义 |
|---|---|
| 0.50 | 核心断裂 |
| 0.80 | 笨拙硬算且有笔误 |
| 1.00 | 常规达标 |
| 1.15–1.25 | 规范严密 |
| 1.30–1.45 | 巧解秒杀 |
| 1.50–1.65 | 压轴题突破 |
| 2.00–2.45 | Donk-tier 超神秒杀（极罕见） |

**严禁打中庸安全分，整组题必须拉开区分度。**
做错题 rating 严禁超过 0.65（有大量正确步骤的笔误最高 0.80）；
超时严重且做错触发经济拖累惩罚。

### 4. 考场极速秒杀思路（betterSolution）

**严禁搬教科书式繁琐长证明。** 必须提供待定系数法、二重积分交换次序、
King 变换、特征多项式秒杀等极简技巧。当前解法已足够精炼则填 `null`。

### 5. 可执行修复动作（advice）

一条精准、直接、**明天即可落地**的刻意练习动作。

## ⚠️ 修法由批改标签决定，不要沿用上一轮自己的推断

**8/30→8/31 的教训**：我把 #143/#147 判为「见过不敢调用」（结论：讲一遍没用），
但 codex 批改标签是**「概念盲区」= 知识缺口**，讲一遍**有**用。
诊断口径错了，修法就全错。

三种「做不对」对应三种修法：

| 类型 | 表现 | 修法 |
|---|---|---|
| **知识缺口** | 不记得公式/定理 | 讲一遍 |
| **见过不敢用** | 记得但不确定能不能主动调 | 逼着调用（讲一遍**没用**） |
| **错误路径自动化** ⚠️ | 复习时**错得比第一次还快** | 入口处用**否定式**规则拦截旧路径 |

**错误路径自动化的识别信号**：复习耗时**低于**首次耗时，且结果照错
（`#7076` 115s→53s、`#10590` 677s→57s 仍 wrong）。
它伪装成「我会做」，最危险。

**修补规则必须用否定式**：「看到 X 应该做 Y」会被旧习惯覆盖；
「看到 X **禁止**做 Z」才能拦住。

## ⭐ 字段长度硬约束（2026-09-03 新增，报告可读性的源头）

**再干净的 UI 也救不了冗长的输出。** 批改报告一屏要装下 8 题 + 断点 + 审计，
所以每个字段都有长度上限。**超限即视为批改不合格，必须重写。**

| 字段 | 上限 | 要求 | 报告中的落位 |
|---|---|---|---|
| `summary` | **40 字** | 一句话点明性质，不复述题目 | 右栏「旁注」引文 |
| `earliestError` | **100 字** | 只定位最早断点 + 说清为什么错在此处；**禁止**顺手把正确解法也写完 | 中栏朱批卡（核心，唯一默认展开的长文本） |
| `betterSolution` | **150 字** | 只给关键技巧与结论，**严禁**完整推导 | 折叠区「标准解法」 |
| `advice` | **50 字** | 一个明天可落地的动作，含可背诵的识别规则 | 折叠区「明日动作」 |
| `errorTags` | ≤ 3 个 | 只用 🔴🟡🔵 三类战术标签 | 右栏标签行 |

**写作纪律**：

1. `earliestError` 与 `betterSolution` **不得重复**——前者说「我错在哪」，后者说「正解是什么」。
   两个字段讲同一件事是报告里最常见的冗余来源。
2. 已判定 `correct` 的题，`betterSolution` 填 `null`，不要为了填满而给一个更慢的解法。
3. 识别规则一律用**否定式**写：`看到 X 禁止做 Z`，而不是 `看到 X 应该做 Y`（见上文修法表）。

### 配套：报告里的「复制给 AI」模板

App 报告提供一键复制，把「题目 + 我的断点 + **我已看过的解法** + 追问要求」打包成提示词。
其中 `betterSolution` 会被放进 **【我已看过的解法】** 段并标注「请不要重复讲」。

**因此 `betterSolution` 必须写成自足的结论**，用户复制走之后没有你的其他上下文也能看懂——
不要写「如前所述」「同上」这类依赖对话上下文的表述。

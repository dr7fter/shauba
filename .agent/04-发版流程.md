# 04 · 版本发布与 GitHub 上传

> 从 `AGENTS.md` 第六节拆出。只在**发版**时读这份。

仓库：`https://github.com/dr7fter/shauba`（公开），分支 `master`。

## 发版三步

```bash
# ① 升版本号（三处必须一致）
#    package.json / src-tauri/tauri.conf.json / src-tauri/Cargo.toml
#    同时更新 RELEASE_NOTES.md（它的内容会成为 latest.json 的 notes 和 Release 正文）

# ② 构建（自动带签名、生成三件套并归档 releases/vX.Y.Z/）
node scripts/release.mjs
#    产出 src-tauri/target/release/bundle/nsis/ 下：
#    刷吧_X.Y.Z_x64-setup.exe + .sig + latest.json + SHA256SUMS.txt

# ③ 推送代码与 tag，然后创建 Release 并上传资产
```

**⚠️ 改版本号后必须同步 Cargo.lock**，否则 `cargo test --locked` 会失败
（`--locked` 拒绝更新 lock 文件）：

```bash
cd src-tauri && cargo update -p shuaba --offline
```

## git 推送

```bash
git push origin master
git tag -a vX.Y.Z -m "刷吧 vX.Y.Z" && git push origin vX.Y.Z   # 新 tag 时
```

## 创建 Release + 上传资产（本机没装 gh CLI，用 API）

```bash
# 取 token（凭据管理器里已有，GCM 授权过一次就持久保存）
export GCM_INTERACTIVE=never
TOKEN=$(printf "protocol=https\nhost=github.com\n\n" | git credential fill | grep '^password=' | cut -d= -f2-)

# 建 Release（body 建议 JSON 写文件再 -d @file，避免 shell 弄坏中文）
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/dr7fter/shauba/releases -d @payload.json
# payload.json: {"tag_name":"vX.Y.Z","name":"刷吧 vX.Y.Z","make_latest":"true","body":"更新说明"}

# 上传资产（关键：exe 必须用 ASCII 名，GitHub 会剥掉中文字符导致 URL 404）
NSIS=src-tauri/target/release/bundle/nsis
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/octet-stream" \
  --data-binary "@$NSIS/刷吧_X.Y.Z_x64-setup.exe" \
  "https://uploads.github.com/repos/dr7fter/shauba/releases/{RELEASE_ID}/assets?name=shuaba_X.Y.Z_x64-setup.exe"
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  --data-binary "@$NSIS/latest.json" \
  "https://uploads.github.com/repos/dr7fter/shauba/releases/{RELEASE_ID}/assets?name=latest.json"
```

`latest.json` 由脚本自动生成，**文件名不能改**——updater 端点固定读
`releases/latest/download/latest.json`。

## 网络坑（本机环境）⚠️ v1.9.0 实测更新

本机 `github.com` 直连受 DNS 污染 / Fake-IP 劫持影响，靠三层保障：

- hosts 已固定 `140.82.112.3 github.com`
  **（v1.9.0 发版时该 IP 的 443 已死**，症状是 `git push` 报
  `Recv failure: Connection was reset` / `Failed to connect ... port 443`。
  实测同日 `20.205.243.166` 可用、`140.82.113.4` 不可用。
  换 hosts 条目**需要管理员权限**——本会话非管理员，故未改系统配置。）
- **非管理员的绕法：本地 CONNECT 隧道**（`prototype/gh-tunnel.cjs`，未入库）
  ```bash
  node prototype/gh-tunnel.cjs &          # 127.0.0.1:18080 → 20.205.243.166:443
  export https_proxy=http://127.0.0.1:18080 http_proxy=http://127.0.0.1:18080
  git push origin master && git push origin v1.9.0
  ```
  只接受 `CONNECT :443`，只在回环监听，进程一停即失效。用完记得 `taskkill`。
- **api.github.com / uploads.github.com 直连一直可用**（不走 hosts 那个死 IP），
  所以建 Release、上传资产、拉资产回来校验都不需要隧道。
- app 内 updater 自动跟随系统代理、失败降级直连（**勿删此逻辑**）

⚠️ hosts 钉 IP 是 DNS 层面的问题，app 内「检查更新」同样走 `github.com`，
所以**在本机 hosts 修好之前，app 内更新检查大概率也失败**——
这不是发布的问题，是本机网络配置过期。

## 发布后验证

⚠️ 文档里原来那条 `curl -sL https://github.com/.../releases/latest/download/latest.json`
在本机会失败（hosts 死 IP），而且**走隧道也会 404**——v1.8.12 的同样链接在隧道里
也 404，与本次发布无关：隧道把所有 CONNECT 都钉到同一个 IP，资产签名 URL 的路由断了。

**可靠的验证是走 API 把资产拉回来比哈希**：

```bash
T=10
curl -sL -H "Authorization: Bearer $TOKEN" -H "Accept: application/octet-stream" \
  https://api.github.com/repos/dr7fter/shauba/releases/assets/{ASSET_ID} -o dl.exe
# 与 src-tauri/target/release/bundle/nsis/刷吧_X.Y.Z_x64-setup.exe 比 sha256
# 应与 SHA256SUMS.txt 完全一致
```

v1.9.0 实测：exe 与 latest.json 双向 sha256 一致，远端大小 5866818 / 61991 字节。

## Release 正文的惯例

正文只放 **RELEASE_NOTES.md 里本版本那一节**（v1.8.12 正文 619 字符，v1.9.0 为 1103），
不是整个文件——用 `prototype/make-payload.cjs` 抽取，别手抄（中文 + 反引号会被 shell 弄坏）。

注意 `latest.json` 的 `notes` 是**整个 RELEASE_NOTES.md**（`release.mjs` 的行为，
v1.9.0 时已 62KB 且每版递增），与 Release 正文不是一回事。
app 更新弹窗会拿到整份 changelog——**待办**：考虑让 `release.mjs` 也只取当节。

## ★ 用户的项目级约定（2026-09-02 明确）

**不做奇怪的接入。批改与写入继续以「和 agent 沟通」为主通道。**

被否决的方案形态：在 Tauri 后端内调 Claude API（`call_claude_api`）。
否决理由：

| 理由 | 说明 |
|---|---|
| 提示词迭代成本 | 提示词是迭代最快的资产（2026-09-01 一天改 5 次）。编译进 Rust 后改一次编一次，`src-tauri/` 有 68663 个文件 |
| 红线风险 | API key 与签名私钥同类，且**更容易被误提交**（出现在配置文件而非 `%USERPROFILE%`） |
| 产品定位 | 破坏「独立、本地、纸笔优先、离线可用」 |
| 成本 | 用付费 + 联网 + 需重写的通道，替换已在跑 + 零成本 + 离线的通道 |

**判据：任何新能力，先问「这件事能不能在 agent 侧（markdown / 脚本 / 只读快照）解决」。**
完整评定见 `考研规划/archive/AI闭环方案评定-20260902.md`。

## codex-inbox 机制

目录：`%APPDATA%\com.shuaba.math\codex-inbox\%`
后端约每 20 秒扫一次（`lib.rs:2235–2306`）。

```
codex-inbox/
├── {taskId}.json      ← AI 写入
├── processed/         ← 处理成功
└── failed/            ← 处理失败（另有 codex_backfill_failures 重试队列）
```

4 种 kind：`recommendation`（推题）/ `batch`（整组批改）/ `paper`（套卷）/ `analysis`（单题批改）。
状态机：`pending → confirmed → applied`；失败进 `codex_backfill_failures` 重试。

## 批改报告的**两条**数据链路（务必分清）

| | 压力模拟（高压演练） | 日常训练（非压力） |
|---|---|---|
| 会话记录 | `supplemental.db` → `pressure_sessions` | **无** |
| 报告存储 | `supplemental.db` → `pressure_reports`（按 session_id） | **主库** `codex_inbox.payload_json`（按 task_id） |
| 结构 | `{grades[], summary{对象}, questionIds, sessionId}` | `{batchAttempts[], summary{字符串}, errorTags, weaknessTags}` |
| 读取命令 | `get_pressure_grading_report(session_id)` | `get_codex_batch_report(task_id)`（v1.6.9 新增） |

**命名误导**：类型 `GradingReport`、组件 `PressureLearningReportView`、函数 `openPressureReport`
现在**同时服务两种模式**，名字是历史遗留。

判断某份 batch 走没走压力模拟：

```sql
-- 主库
SELECT task_id, status FROM codex_inbox WHERE kind='batch' ORDER BY rowid DESC;
-- supplemental.db
SELECT session_id, status, task_id FROM pressure_sessions ORDER BY created_at DESC;
-- task_id 出现在 pressure_sessions 里的，才是走了压力模拟的
```

## 好友同步 = 直连坚果云服务器，不碰本地同步盘

「关掉坚果云桌面客户端会不会同步失败」→ **不会**。
WebDAV over HTTPS 直连 `https://dav.jianguoyun.com/dav/`，代码**显式拒绝本地路径**，
`capabilities/default.json` 无 fs 插件权限。

真正会失败的只有三种：断网、应用密码被重置或禁用、云端共享文件夹被删。
常量：`MAX_PAYLOAD_BYTES = 256KB`、连接超时 4s、总超时 8s、ETag 差异缓存跳过 GET。

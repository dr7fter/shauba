## 一、三不伪造（最高优先级）

| 禁止 | 说明 |
|---|---|
| **不得把一次做对判定为稳定掌握** | 稳定掌握需要重复证据 |
| **不得在没有结构化关系时称为迁移题** | 无结构关系 → 必须显示「结构证据不足」 |
| **不得假装已完成图谱标注** | 未知节点必须标记 `unclassified` |
| **不得伪造历史指纹** | 题目指纹只允许按本轮候选题临时识别；如需缓存，必须有明确字段、来源和失效策略 |
| **不得伪造变式关系** | 替换题没有可靠结构关系时必须明示 |

## 二、选题与题组约束

- 只能从题库目录选题（**不造题号**）
- 必须说明：目标节点、题目角色、考法变化、成功标准
- **不得超过时间预算 15%**
- **不得连续推荐三道同构题**
- 优先处理高信心错误和**反复出现**的错误

**阶段变化规则（C3）**：

| 阶段 | 一次改变几个因素 |
|---|---|
| 暴露 / 基础 | 一个 |
| 巩固 | 两个 |
| 迁移 | 多个，但**必须有中间证据** |
| 综合 | 跨分支组合 + 时间限制 |

新颖度等级：`same_template` / `numeric_change` / `condition_change` /
`method_choice` / `structure_transfer` / `cross_topic`

**迁移 Transfer（20% 权重）必须记录是否为不同题 / 不同结构。**

## 三、题组校验（AI 输出进入训练前，App 侧 9 条）

1. 题号存在且属于本地题库
2. 题目未重复，或重复有明确复习理由
3. 题目知识节点在目录中存在
4. 题目角色与指纹匹配
5. 覆盖节点达到用户需求中的最低集合
6. 题组预计时间在预算范围内
7. 难度和新颖度没有不合理跳跃
8. 迁移题存在结构化关系
9. 题组至少包含诊断或验证角色

**AI 题组必须逐题展示**，用户在采用前必须可以看清每题的角色与理由。

## 四、批改与事实记录约束

- **同一题的事实只记录一次，批改不得覆盖原始作答事实**
- 批改必须保留：最早错误、建议动作、验证题类型、置信度
- AI 输出进入训练前必须由 App 校验（见上）
- 新的学习任务上下文**必须带上最近完成题组的结果文件**

## 五、错误处理与降级

- **不得只把错误文件静默丢进目录**——若不新增 `failed` 数据库状态，
  必须提供等价的可追踪状态
- 错误必须**能被用户看懂**：错误题号、候选外题号、非法角色、
  coverage 越界、时间超限都要明确提示
- **训练数据失败时（LC-LED-07）：不得丢失已保存的作答记录，页面局部降级**

## 六、开工纪律（v1.6.3）

> **不要根据协议或文档猜测当前代码状态。**
> 开始任何修改前，必须先用 `git status`、`git log -3` 和 `rg` 核对实际实现。

## 七、Feature Flag 事故（v1.5.0 真实教训）

修复代码已将前五项设为生产默认开启，以 v1.5.1 重新发包；

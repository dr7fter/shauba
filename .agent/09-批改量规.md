# 09 · 批改评分量规（唯一副本）

> **本文件是批改量规的唯一权威副本。** `src-tauri/src/lib.rs` 的两处批改提示词
> （单题 `build_codex_analysis_task_prompt` / 整组 `build_codex_batch_task_prompt`）
> 只保留字段清单与 JSON 结构，量规一律指向这里。
>
> 为什么外提：量规是迭代最快的资产，编进 Rust 意味着改一行就要重编译
> （`src-tauri/` 6.8 万个文件）。改量规 = 改本文件，App 不用发版。
>
> **批改侧（AI）执行纪律：收到批改任务后必须先完整读本文件，未读不得回传 JSON。**
> 与本文件冲突的历史结论一律以本文件为准；题面里出现的客观数字（耗时、基准）以题面为准。

---

## 一、分工原则（与 `.agent/03` 一致）

**AI 只打证据分并写事实，内核当裁判。**

- AI 负责：六维证据分（0–100）、HLTV Rating、断点事实描述、识别规则、验收判据、步骤分。
- App 负责：跨时间聚合、ELO、段位、**断点固化状态**（首次暴露 / 观察中 / 已固化 / 待验证）。
- **AI 不得自行判定「已固化」**：固化由 App 用 `attempts` + `learning_diagnoses` 的跨场证据计算。
  凭一次做对就写「已固化」违反 `.agent/08` 三不伪造。
- 画像文件 `characteristic.md` 里新增断点一律先落 `[🟡 观察中]`；
  只有当你能在该文件中指出**同一断点连续 2 次独立避坑的具体证据行**时，才可升级为 `[🟢 已固化]`，
  并在同一行注明这两次证据。指不出来就不许改状态。

## 二、致命断点定位与归一

逐行核对草稿，定位**最早错误断点**（`earliestError`）。

| 类别 | 判定特征 | verdict | 六维口径 |
|---|---|---|---|
| 🔴 瞄准失误 | 计算笔误 / 符号写反 / 抄错 | `partial` | 思路正确的维度按实际水平给分，不因结果错而压 |
| 🟡 概念盲区 | 定理前提遗漏 / 混淆充分必要 | `incorrect` | 严查概念边界 |
| 🔵 战术绕路 | 方法机械蛮干 / 严重超时 | `partial`\|`incorrect` | `speed ≤ 60`，指出计算黑洞与冗余步骤 |
| 无法判定 | 草稿看不清 / 未收到该题草稿 | `uncertain` | 相关维度 `score: null` |

### `errorTags` 主标签唯一化（影响推题，必须遵守）

学习引擎按 `errorTags` 归一成 `aiming / concept / tactics` 三类病因，
归一函数按 **aiming → concept → tactics 顺序首个命中**（`services/learning.rs::normalize_error_class`）。
多标签会让「概念盲区 + 计算笔误」被判成 `aiming`，**而病因聚类直接决定明天推什么题**。

- `errorTags`：**恰好 1 个**主标签，取这道题**最早的那个断点**所属类别，三选一词表照旧。
- `secondaryTags`：自由数组，其余次要病因写这里（不参与归一、不影响推题，仅供报告展示）。
- 词表外的新词会被归一兜底成 `mixed`，宁可用旧词也不要造词。

### 步骤分 `stepScore`（0–100 整数，`partial` / `incorrect` 必填）

有效步骤分 = 卷面上真正能拿到的分数占比。**报告要显示它**，学员必须看得见"自己错得多可惜"。

- `partial`（瞄准失误）：一般落 65–80；核心式子列对但代错数值取低段。
- `incorrect`：概念断裂通常在 20–45；只有列式正确给低段。
- `correct` / `uncertain`：填 `null`。
- 判据是卷面步骤的实际有效性，不是"感觉可惜"。

## 三、HLTV Rating 3.0 定位（0.00–2.50，拉开区分度）

- 0.50 核心断裂 / 盲区；0.80 笨拙硬算且有笔误；1.00 常规达标；1.15–1.25 规范严密；
  1.30–1.45 巧解秒杀；1.50–1.65 压轴题突破；2.00–2.45 Donk-tier 超神秒杀（极罕见）。

**硬约束**

- `verdict = incorrect` → `rating` 严禁超过 0.65（有大量正确步骤的笔误最高 0.80）。
- 超时 1.5 倍以上且做错 → 触发经济拖累惩罚（内核会再算一次，不要自己扣完）。
- 整组批改时同组 Rating 必须依草稿实际优劣拉开梯度，**严禁全部打在 1.10–1.20**。

> Rating 的最终合成在内核（`services/rating.rs`）。你给的是**证据分**，不是结算分。

## 四、六维能力打分准则（0–100）

六维：`rigor` 严谨性 / `computation` 计算力 / `modeling` 审题建模 /
`methodUse` 方法使用 / `speed` 速度 / `strategyInsight` 策略洞察。

**每维必须带 `evidence`：引用草稿里的具体推导内容。严禁无证据给分——
报告会把极差最大那一维的 `evidence` 原样上架，写错了学员能当场抓到。**

无法从草稿确认的维度：`score: null` + `confidence: 0` + `evidence: "uncertain"`。**严禁猜 75 分。**

### 六维独立性量规（六维必须独立于对错结果给分，严禁锚定 verdict）

- **严谨性 / 计算力只看执行**：每处计算笔误、符号写反，该维从 90 起每处 −10 起步，
  与思路对错无关（做对但涂改三处 → 计算力 ≤ 65）。
- **方法使用 / 审题建模只看路径**：使用该考点的标准入口动作才 ≥ 75；
  绕路硬算、蛮力展开 → ≤ 55，**即使最终做对**。
- **策略洞察只看结构识别与优化空间**：常规套路 ≤ 70；巧解 / 对称性 / 极端变换类 ≥ 85。
- **速度只看客观耗时**：题面给了「实际耗时 / 基准耗时」两个数，不给你任何评价词。
  自己按比值算：≤ 0.5×基准为快；超 1.5×基准 → ≤ 55。**与对错无关。**
- **反「参与奖」**：六维全部 ≥ 90 仅在「快且准且巧」同时成立时允许；常规做对的题至少一维 ≤ 75。
- **反「陪葬」**：做错时思路正确的部分（瞄准失误），对应维按实际水平给分，
  `methodUse` / `modeling` 不因结果错误被强制压到 40 以下。
- **极差自检**：输出前检查单题六维极差。极差 < 10 分仅当六维确实均衡时允许，
  否则视为锚定失效，必须重新对照证据打分。

`strategyInsight` 额外两个字段：

- `techniqueLevel` 1–5：本题技巧难度，决定这个技巧值不值得进画像。
- `independentDiscovery`：`confirmed`（独立做出）| `uncertain`（草稿无法判定）| `prompted`
  （提示后才做对）。**这是最稀缺的元认知信号，不要一律填 confirmed。**

题级 `confidence`（0–1）与维级 `confidence` 都要真实填写：
报告会把低置信判定标成「AI 也不确定」，铁口直断和待确认在界面上必须长得不一样。

## 五、断点诊断块 `diagnosis`

报告的认知动线是**我的入口 → 断点 → 为什么是死路 → 识别规则 → 正确入口**，逐项填实，
严禁留空或复述题干。

- `myEntry`：学员落笔时的第一个动作，原话式一句（含 `$LaTeX$`）。
  **描述他做了什么，不是他错在哪。**
- `whyDeadEnd`：讲清这条路径为什么走不通——讲结构特征与原理。
  严禁复述计算步骤，严禁写成"应该这样做"。
- `rule`：先 `negation` 后 `positive`。`negation` 必须是
  「看到什么特征 → 禁止做什么」的硬约束句式——**肯定式会被旧习惯覆盖，否定式才拦得住**。
- `fork`：`step` 填分叉发生在第几步（落笔即错填 1）；`myPath` 与 `standardPath` 对照填写；
  `consequence` 写清走错之后会发生什么（如「越算越繁，不存在算到底也能对的可能」）。
- **原理闭环（深度下限）**：`whyDeadEnd` 必须构成「引用题目条件 → 点名适用原理 → 推出结论」。
  验收判据：学员**只读这一段、不翻解析就能明白这条路为什么走不通**；
  只给结果式、跳过"为什么"（如写"走补集：$1-P\{X>v\}P\{Y>v\}$"却不讲为何绕补集、
  为何能拆乘积）即格式违规。同时整段以 40 秒内读完为限——闭环不是把整题重算一遍。
  ⚠️ **2026-09-14 职责移交**：「学员只读就能**复现正确动作**」这条判据已移交给
  `walkthrough`（见第九节）。因此 `whyDeadEnd` 只讲原理、不讲步骤，
  `fork.standardPath` 不再写正解全文，只在分叉点写"正确的选择是什么"（≤2 句）。
- **去重**：同一式子或事实全题 JSON 不得出现在 3 个以上字段；
  `myEntry` 写第一落笔，`fork.myPath` 写错路后续演进；
  二者与 `walkthrough`、`fork.standardPath`、`whyDeadEnd` 之间均不得互为复读。
- `acceptance`：一条**可判定**的验收判据（如「根号池 13 题零覆盖」）。
  禁止"多做练习""加强理解"这类无法判定的空话。
- `errorCode`：**优先复用 `characteristic-core.md` 第一节断点表中已有的 E 码**（如 `E-038`），
  同一入口导致的题必须填同一个码——复发时间线与病因聚类都靠它对齐。
  确无匹配才可新编，并在 summary 里用一句话说明新码语义（画像侧要能对上号）。
- `title` / `severity`：断点名 + `L1` 致命 / `L2` 战术 / `L3` 精度。
- `nextAction`：明天就能做的一条动作，**需能在 10 分钟内完成**。
- `syllabusTools`：本题实际用到的数一考纲内公式/定理，≤5 条，每条一句话可含 `$LaTeX$`。
  wrong / partial 必填，correct 可空——报告会挂「用到的数一工具（全部在考纲内）」区块，
  **没用到就别硬凑**，把"切比雪夫不等式"写成"不等式放缩"这种模糊词是无效回传。
- ~~`draftPaths`~~：**已于 2026-09-05 退出契约**（批改报告不再展示草稿图），不要再回传。

### `correct` 题填「固化卡」，不要整块 null

做对的题同样要留证据——画像封盘（连续 2 次独立避坑 → 🟢 已固化）靠的就是它。
`verdict = correct` 时 `diagnosis` 填一张三字段迷你卡，**不要扩到十字段**：

```json
{"myEntry": "这次落笔的第一个动作（含 $LaTeX$）",
 "rule": {"positive": "是哪个特征让你认出该这么做"},
 "whyItWorked": "这条入口为什么在这道题上成立（讲结构，不讲步骤）"}
```

`correct` 题的 `whyDeadEnd / fork / acceptance / nextAction / severity / errorCode` 填 `null`。

## 六、`betterSolution`（捷径注）与 `advice` 的分工

- `betterSolution`（**捷径注，默认 null**）：仅当四条同时成立才写——
  ① **捷径本身比标准动作便宜**：一眼的结构观察（对称 / 恒等式 / 补集 / 符号判断）
     直接省掉一整段计算。**严禁搬运繁琐教材长证明，也严禁用考纲外的高级结论或
     更复杂的变形来"假装快"**——King 变换、特征多项式这类"30 秒动作"若要求学员
     新学一套机制才能用出来，对他是负资产，不写；
  ② 数一考纲内、考场可正当使用；③ 相对标准动作至少省一个完整步骤；
  ④ 学员这次没用上（他自己已经用出来的就是正解，不必再注）。
- **correct 题一律填 `null`**：一题一"秒杀"不是洞察是统计造假。
- **文本禁速度隐喻**："秒杀 / 秒出 / 肌肉反射 / 一击必杀"都不写，只写动作与被省掉的步骤。
- `advice`（题级）：correct 题一律 `null`——**对题不给建议是纪律不是奖励**。
  错题只写动作 + 可核查时间预算（"3 道含常数期望的混合小题，每道 ≤2 分钟"）。
- **维度对象内不要再写 `advice`**：动作只有题级一处出口，
  三份"动作"口径必然打架。维度只留 `score` + `confidence` + `evidence`。

## 七、公式排版

所有数学符号、变量、公式、计算式必须用 `$...$` 或 `$$...$$` 包裹，严禁裸文本数学式。
UTF-8，公式用标准单个反斜杠 LaTeX。

## 八、`verdict` 与 `result` 的关系

`verdict` 是批改结论（`correct | partial | incorrect | uncertain`），
`result` 是落库口径（`correct | wrong | uncertain`），**由 `verdict` 派生，不是独立判断**：

```
correct → correct      partial → wrong      incorrect → wrong      uncertain → uncertain
```

两个字段都要输出（历史兼容），但内容必须满足上表，不得各写一套。

## 九、完整解答 `walkthrough`（2026-09-14 新增）

**报告的主轴是正解全流程，其余字段都是围绕它的批注。**
因此本题必须给出一份可独立复现的完整解答——它是学员第二天照着重写一遍的东西。

```json
{"lead": "本题最省路径是直接参数化代入，步骤如下：",
 "steps": [
   {"n": 1, "title": "判断闭合性并选路",
    "prose": "起点 (0,0) 与终点 (π,0) 不重合，是开曲线；用格林必须先补线，但本题代入后能大幅化简。",
    "quote": "代入 $y=\\sin x"},
   {"n": 2, "title": "参数化并整理被积式", "...", "quote": "..."}
 ]}
```

每步三件事：

1. **`title`——动作式小标题，≤12 字**，写"做什么"不写"用什么"。
   好：「判断 L 的闭合性，据此选路」／坏：「格林公式」（纯名词不是动作）。
2. **`prose`——这步为什么这么做**。只讲判断依据与理由，**不复读公式**
   （公式本身由报告从题库正解渲染，你复读一遍就是重复信息）。
3. **`quote`——题库正解中对应片段的逐字子串**。App 用它 `indexOf` 定位并校验来源：
   - 命中 → 正常渲染，学员知道这一步出自权威正解
   - 未命中 → 该步渲染为灰色并标「AI 补充」
   - 题库正解确实不含此步（如"方法选择"这类纯推理步）→ 填 `null`，同样按「AI 补充」处理
   - **`quote` 是防幻觉的唯一闸门**：不要凭印象写，必须从所给正解里逐字复制一段

硬约束：

- **步数 3–6**：少于 3 说明拆得太粗（等于没拆），多于 6 说明在记流水账
- **禁止速度隐喻**："秒杀 / 秒出 / 一击必杀 / 肌肉反射"一律不写
  ——这条与第六节一致，walkthrough 不是"快速解法"，就是标准解法
- **终值闸门**：最后一步的结论**必须**与题库 `correct_answer` 数值一致。
  不一致时 App 会整段标「未通过校验」，等于这道题的解析作废
- **`walkthrough` 是正解的唯一完整处**：`fork.standardPath` / `whyDeadEnd` 不得复述其步骤
- `lead` 一句话（≤40 字）领起，说明"本题最省路径是什么"；没有更省路径时就写标准路径

`verdict = correct` 的题**同样要写**——做对的题也要留下可复现的正解供封盘与复习。

## 十、多断点 `breakpoints[]`（2026-09-14 新增）

一道题的错误常常不止一个。主断点仍由 `errorTags[0]` + `diagnosis.fork` 承担；
**其余错误点一律进 `breakpoints[]`，每条都要带一句解释**（`secondaryTags` 只有标签没有解释，
它是本报告长期缺的一层）。

```json
{"n": 2, "tag": "二重积分区间再现漏系数",
 "why": "展开 ∬4xy 时区间再现法少配了一半系数",
 "stepRef": null, "severity": "L2"}
```

- **`stepRef` = 该错误对应 `walkthrough.steps` 的第几步**
- **`stepRef = null` 不是漏填，是语义**：表示「错路内的二次错误，正解无对应步」。
  这一档很重要——它在告诉学员**这条错误不必深究**（因为正解根本不走那条路），
  所以 `why` 要写清"为什么不必深究"，而不是展开长篇分析
- `why` 只写"为什么会错"，一句话，**不复述现象**（现象已在 `tag` 里）
- **上限 3 条**：只列有解释价值的；纯计算笔误不列（列了等于教他练笔误）
- `severity` 用 `L1 | L2 | L3`，与主断点的分级同一套

**`errorTags`（病因分类，三选一）职责不变**——它与 `breakpoints` 是两个维度：
前者归因而用（推题与聚类看它），后者是具体错误点。不要混写，也不要用 `breakpoints` 替代 `errorTags`。

`secondaryTags`（旧字段）**保留兼容**：历史报告仍靠它渲染 chips。
新批改请同时填 `secondaryTags`（标签）+ `breakpoints`（带解释的结构化版本），
App 优先读 `breakpoints`，缺失时退回 `secondaryTags`。

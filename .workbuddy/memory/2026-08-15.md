## 刷吧 Codex batch 回传 JSON 校验坑
- 给刷吧回传 batch 批改 JSON 时，AGENTS.md 给的示例 schema 是**简化版**，实际 `src-tauri/src/lib.rs` 的 `CodexPayload` 结构体（`#[serde(rename_all="camelCase")]`）顶层还有 4 个无默认值必填字段：`errorTags`、`weaknessTags`、`confidence`、`recommendedQuestionIds`。缺任何一个都会 `serde_json::from_str` 失败，文件被 `scan_inbox` 移到 `codex-inbox/failed`（前端显示为“JSON 格式或字段不完整”）。
- 正确写法：batch JSON 顶层必须同时含 `schemaVersion,kind,taskId,summary,errorTags,weaknessTags,confidence,recommendedQuestionIds,batchAttempts`。batch 类型下 `errorTags/weaknessTags/recommendedQuestionIds` 填空数组即可，`confidence` 给整组值。
- 文件名必须带 `.json` 扩展名，否则 `scan_inbox` 直接跳过（不处理也不报错）。
- 入库还会校验：每题 `result∈{correct,wrong|uncertain}`、`selfRating∈1..4`、且 `questionId` 必须真实存在于题库 `questions` 表（否则仅 log warn、文件留在收件箱根目录不进 processed）。

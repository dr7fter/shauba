## 0. 给执行 Agent 的总任务

在不替换旧数据页、不污染历史竞技账、不把低置信度证据写入核心画像的前提下，完成 v1.5.0 的“双引擎学习闭环”：

```text
压力/排位暴露问题
  -> 学习证据诊断
  -> 靶向修复
  -> 明确变式验证
  -> 受控延迟复习
  -> stable gate 验收
  -> 下一次压力/排位复验
```

- **竞技引擎**回答“当前真实限时表现如何”：Rating、ELO、段位、压力报告。
- **学习引擎**回答“哪里不会、为什么不会、下一步做什么”：证据、五指标、错题状态机、推荐与复习。
- **激励层**回答“为什么愿意持续做”：XP、成就、连续完成、白名单好友动态。
- AI 只提供诊断证据；确定性内核决定状态、权重、ELO 与幂等结算。

### 1.1.1 A/B 已收口的不变量（发布前仍须人工复核）

以下不变量已经由实现、单元测试和回放覆盖；人工验收仍需确认真实桌面流程与文案没有偏差：
1. **非压力批量回传只做裁决，不新建作答**：任务创建时必须冻结 `task_id -> question_id -> source attempt_id?` 映射。已绑定的普通作答回传后只能新增 diagnosis / adjudication sidecar；不得插入新的 `attempts`、修改 `progress`、新增或修正 `elo_events`。任务创建时未作答的题保持未绑定，不猜“最新同题作答”。
2. **单题确认与启动回填保持历史不可变**：诊断确认/回填不得更新原 `attempts`，不得写隐式 `codex_review` ELO correction；AI 的 rating、置信度与六维必须留在追加式诊断/证据侧车中。
3. **stable 只接受结构化关系**：变式必须带显式 `variant_of_question_id`（或等价受控任务关系）；延迟复习必须绑定真实 `review_task_id`、被标记为需要延迟复习，并以成功时间间隔 `$\ge 24\,\mathrm{h}$` 验证。不同题号和 `mode` 字符串都不能充当这两类证据。
4. **旧任务迁移不重开生命周期**：旧空 `semantic_fingerprint` 只能补齐指纹/关联，不能把 `completed`、`closed` 或 `archived` 的 review task 重开。
5. **必须有端到端不变量测试**：确认普通单题/整组诊断后，`attempts` 与 `elo_events` 的数量及内容保持不变；只允许新增可追溯的 diagnosis/evidence。该测试通过前，文档不得标注 Phase A/B 已验收。

## 2. 三本账与模式边界

### 2.1 竞技账 Competitive Ledger

包含 `elo_events`、压力会话、Rating、段位、赛季和高压报告。只有压力/排位模式且批改完整、结果可信、结算幂等时才允许产生新的竞技结算。

- 训练、复习、普通刷题：不更新 ELO；
- `uncertain`、未确认批改、重复任务、缺失报告：不得结算 ELO；
- 历史事件只读保留，不通过 v1.5.0 回放覆盖 `rating_after`；
- 新规则必须写入 `rulesetVersion` 与赛季边界，才能在未来做严格公式回放。

### 2.2 学习账 Learning Ledger

包含 evidence、diagnosis、skill state、review task、recommendation plan 和错题状态。它可以接收压力模式暴露的问题，也可以接收非压力训练证据，但必须经过置信度门控。

### 2.3 激励账 Motivation Ledger

包含 XP、成就、连续完成和好友可见播报。它只消费已经确认的学习/竞技事件摘要，不反向修改学习状态或 ELO。好友广播必须脱敏、幂等、可撤回，并明确最后同步时间。

### 2.4 模式矩阵

| 模式 | 学习账 | 竞技账 | 激励账 | 允许提示 |
|---|---:|---:|---:|---|
| 今日训练/普通刷题 | 是 | 否 | 可发 | 可有诊断、批量 AI 草稿入口 |
| 复习/错题修复 | 是 | 否 | 可发 | 可有受控回忆提示 |
| 压力/排位 | 暴露问题 | 是，仅完整可信结果 | 可发 | 无即时提示，遵守压力规则 |

## 3. 统一证据与置信度门控

### 3.1 唯一门控表

| 证据状态 | 核心影子画像 | 任务/复核建议 | ELO/正式结算 | 权重 |
|---|---:|---:|---:|---:|
| `uncertain` | 否 | 是，可要求人工复核 | 否 | 0 |
| `confidence < 0.60` | 否 | 是，仅人工复核 | 否 | 0 |
| `0.60 <= confidence < 0.75` | 否 | 是，可生成任务/复核建议 | 否 | 0 |
| `0.75 <= confidence < 0.90` | 是 | 是 | 不因低置信度直接结算 | 0.5 |
| `confidence >= 0.90` | 是 | 是 | 压力模式满足全部条件时可结算 | 1.0 |

`confidence` 必须是有限数，范围应被规范化到 `[0, 1]`。缺失、非法、NaN、Infinity 均视为没有可采纳置信度，不能默认成 1.0。

### 3.2 精确关联规则

- Codex signal 只有在拥有并匹配 `attempt_id` 或 `diagnosis_id` 时，才可以为对应 attempt/diagnosis 提供置信度；
- 没有精确关联时，**不得**用相同题号、相同日期、相同文本或“最近一条 signal”回填 attempt；
- 未确认 signal 单独统计，不能参与 attempt 质量、画像、正确率、推荐完成或 ELO；
- 同一 attempt 存在多个已确认 signal 时，使用确定性去重策略并保留审计来源；
- `uncertain` 的 verdict/result 优先级高于数值置信度，始终不进入核心画像。

### 3.3 五指标定义

- **掌握 mastery**：知识点目标是否能正确完成；
- **流畅 fluency**：在正确或部分正确前提下，结合题型基准时间与步骤效率评估；做错不能靠自评刷高；
- **迁移 transfer**：明确标记为变式/迁移且绑定原题来源的题目上成功；不同题号本身不构成迁移；
- **保持 retention**：受控 review task 中，经过规定间隔仍成功；
- **画像置信度 confidence**：证据质量、样本量、题目多样性和冲突综合值，不是掌握分的同义词。

## 4. 变式、延迟复习与 stable gate

### 4.1 变式证据

变式成功必须同时满足：

1. 有明确的 `variant`/`isVariant`/`transferVerified` 等受控标记；
2. 有 `originQuestionId`/`origin_question_id` 等原题关联；
3. 原题 ID 与当前题 ID 均有效且不同；
4. 作答结果为 `correct`，且置信度至少 `0.75`；
5. 证据不是单纯重复原题或仅题号不同。

历史没有这些结构化字段时，迁移显示为 `unavailable`，stable gate 失败，不生成 `stable_candidate`。

### 4.2 延迟复习的冻结定义

延迟复习只认以下精确条件，间隔必须是 **`>= 24h`**，不是“隔天”、不是“约三天”、不是自然日差：

```text
review_task_id 精确关联到存在的受控 review_tasks 行
AND review_tasks.delayed_review_required = true
AND review_started_at 存在
AND previous_success_at 存在
AND review_started_at - previous_success_at >= 24 小时
AND outcome = correct
AND confidence >= 0.75
AND 不以 mode 字符串作为延迟复习证明
```

未来实现必须由受控 `review_task` 生成并绑定这些字段；外部脚本、用户手填字段或仅凭时间戳推断都不能创建正式延迟复习证据。

### 4.3 stable gate 必须显式可审计

每个技能/降级题目组都必须输出：

- `stableEligible`：布尔值；
- `conditions`：每项门槛的实际值、要求值和是否通过；
- `failedReasons`：稳定、机器可读的失败原因数组；
- 证据来源和时间范围。

建议默认门槛：

| 条件 | 要求 |
|---|---|
| 有效核心证据 | `>= 3` 次 |
| 不同题目数 | `>= 2` |
| 明确变式/迁移 | 至少 1 次成功 |
| 受控延迟复习 | 至少 1 次成功，严格 `>=24h` |
| 近期错误 | 无近期同类概念错误 |
| 画像置信度 | `>= 0.75` |
| 指标底线 | mastery、transfer、retention 分别达到实现常量 |

任意条件缺失或失败，`stableEligible=false`。缺分类时按 `question_id` 单独降级；没有题号时按 attempt 单独降级；不得把所有缺分类数据聚成一个“未分类”技能。

## 5. ELO 历史审计边界

### 5.1 不允许的伪重放

历史 `elo_events` 如果没有 `rulesetVersion`/`ruleset_version` 或 `seasonId`/`season_id`，回放脚本必须把：

- `formulaAudit.status` 标为 `unknown`；
- `formulaAudit.strictDeltaReplay` 标为 `unknown`；
- 不套用当前或猜测版 expected、mastery、难度、K 值公式；
- 不输出“公式错误”“delta 错误”这种伪 error。

如果历史含有版本或赛季元数据，也只能标为 `plausible_only`，除非同一 ruleset、赛季边界、初始值、输入字段和算法版本完整可证，否则不能宣称严格重放。

### 5.2 允许的结构审计

只审计可以不依赖未知公式的事实：

- `attempt_id`、`question_id` 引用是否存在且一致；
- 时间顺序是否明显倒置；
- `performance`、`expected`、`rating_after` 等有限数值和范围是否合法；
- `rating_after` 与相邻 `delta` 的链是否连续；
- 非压力模式事件清单；
- `uncertain` 作答是否产生历史结算；
- 同一 attempt 是否重复结算；
- 缺失事件、缺失规则字段等迁移风险。

链不连续只输出结构 warning，可能是赛季重置、历史缺口或旧规则，不能自动判为公式错误。仓库 `AGENTS.md` 中的当前公式只能作为说明文字，不能套到无版本历史。

## 6. 回放脚本使用契约

脚本：`E:\刷吧\scripts\replay_v150_learning.py`

### 6.1 只读与输出文件安全

- 数据库使用 SQLite `mode=ro` 和 `PRAGMA query_only=ON`；
- 脚本不执行任何数据库写入，也不修改题库或应用文件；
- `--json PATH` 解析并 `resolve()` 后，拒绝与数据库同路径；
- 拒绝目录、既有文件和不存在的父目录；
- 使用独占创建（`O_EXCL`），因此并发 race 也不会覆盖已有报告；
- 报告路径是唯一可能新建的文件，**“DB 只读”不等于“报告路径不会写文件”**；
- 不提供危险的默认覆盖或 `--force`。

### 6.2 Windows 示例

```powershell
python -X utf8 E:\刷吧\scripts\replay_v150_learning.py --help
python -X utf8 E:\刷吧\scripts\replay_v150_learning.py --db "$env:APPDATA\com.shuaba.math\shuaba.db" --as-of 2026-08-24 --limit 20
python -X utf8 E:\刷吧\scripts\replay_v150_learning.py --db "$env:APPDATA\com.shuaba.math\shuaba.db" --json E:\temp\shuaba-v150-report.json
```

输出文件必须事先不存在，目录必须事先存在。需要重跑时指定新的文件名；不要删除数据库，不要把输出写到数据库路径。

### 6.3 报告解释

报告是**影子分析**：只读历史并生成报告，不写回数据库、不导入画像、不更新推荐计划、不改变 `attempts`、`progress`、`elo_events`。报告里的 `stableEligible` 是回放门控结果，不是已写入产品状态。

## 7. Phase C 执行顺序

> 当前进度：C0-C3 及 C4 的只读摘要/诚实空态已完成自动验证；C4 的正式 XP、成就和好友广播放量，以及 C5 的正式启用与发布，仍未执行。

### C0：契约、回放与数据投影

- 固化本文门控常量和字段命名；
- 保持 Phase A/B 的批量批改、好友、压力报告行为；
- 先让回放脚本在真实 DB 和临时 fixture 上通过安全测试；
- 新投影只读，不回写历史；
- 所有新数据库写操作只能通过 Tauri command 和迁移测试完成。

### C1：新学习中心骨架

- 新增独立 `LearningCenterView`；
- 旧数据页入口和行为不变；
- 首屏先显示数据状态、今日目标、五指标和证据限制；
- 失败采用局部错误，不阻塞答题主流程。

### C2：五指标与稳定门

- 输出每项条件与失败原因；
- 迁移/保持缺证据时显示“不可用”，不能显示 0 伪装成未掌握；
- 低置信度只进入任务/复核队列；
- 错题关闭必须等待变式和延迟复习证据。

### C3：四轨推荐影子运行

四轨默认比例仅是可解释计划初值，不是 ELO：

- 修复 40%；
- 巩固 25%；
- 迁移 20%；
- 挑战 15%。

推荐必须显示理由、证据来源、预计耗时和完成条件；在影子回放与人工验收完成前，不替换 TodayView 的真实题队列。

### C4：好友、报告与激励闭环

- 好友动态只播报白名单事件：完成题组、Rating 变化、比赛完成、报告可读；
- 公开报告必须脱敏，并区分“报告已上传”“报告已确认”“报告不可用”；
- 学习中心只展示摘要，阅读完整报告沿用安全的报告容器；
- 训练 XP/成就与 ELO 视觉和数据字段分开。

### C5：逐步放量与回滚

只有回放、构建、Rust 测试、UI 验收、数据一致性和性能均通过后，才逐个开启 feature flag。任何异常先关对应开关，不删除历史，不用重算掩盖问题。

## 10. 回滚与残余风险处理

出现以下任一情况立即关闭对应 flag：

- 学习中心白屏或阻塞 TodayView；
- 低置信度进入正确率、画像或 ELO；
- 旧 ELO 被回放覆盖；
- 同一报告重复结算；
- 没有结构化变式/复习证据却显示 stable；
- 好友报告越权或过期时间不明确；
- 推荐题目不存在、刷新洗牌或无限重排；
- 坚果云/网络故障阻塞主训练流程。

历史 schema 缺少 attempt/diagnosis、variant、review_task、rulesetVersion 时，v1.5.0 只能显示“证据不可用/审计未知”，不能通过猜测补齐。这个限制是可接受的残余风险，待未来受控写入新证据后自然消除。

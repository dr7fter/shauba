# 刷吧 v1.6.0 自适应学习引擎更新方案书

版本：Draft 1.0  
日期：2026-08-26  
基线：v1.5.5

## 1. 版本定位

v1.6.0 不把 TodayView 改造成信息面板，也不把学习中心做成静态数据看板。它要完成的是：

> 用 AI 理解用户当下的学习需求，用考点图谱和题目结构约束 AI 的推荐，用 App 记录事实并验证推荐是否有效。

最终闭环：

```text
自然语言需求
  -> 当前学习状态快照
  -> 考点分支覆盖规划
  -> AI 生成结构化题组
  -> App 校验题目与约束
  -> 用户确认/调整
  -> TodayView 清爽作答
  -> 批改与证据入账
  -> 即时修复、延迟回忆、变式迁移
  -> 结果回传 AI
  -> 下一轮题组调整
```

### 不改变的体验

- TodayView 继续保持当前纸笔优先、低干扰布局。
- 刷题时不展示复杂考点树、推荐理由和心理指标。
- 题库源 `E:\考研资料\题库-大观园` 继续只读。
- 不连接 Obsidian 或拾遗录。
- 日常训练不直接改变正式 ELO；压力/排位账与学习账分离。

## 2. 成功标准

### 用户结果

1. 用户在学习中心用一句话描述需求，30 秒内得到可理解的题组方案。
2. 每个题组能说明覆盖了哪些考点、改变了哪种考法、为什么现在推荐。
3. 用户适应标准考法后，系统会逐步改变条件、表示、方法入口和知识组合，而不是继续盲抽同类题。
4. 用户能一键勾选、替换、加入自定义队列或开始训练，不需要手工编辑 JSON。
5. 完成题组后，下一轮推荐会使用真实作答结果，而不是只看一次正确率。

### 工程结果

1. AI 不能编造题号、知识点或稳定掌握结论。
2. 所有推荐、校验、采纳、完成和拒绝都有可追溯记录。
3. AI 输出失败时，旧版推荐和 TodayView 仍可正常使用。
4. 关闭全部 1.6.0 feature flags 后，行为与 v1.5.5 等价。
5. `npm run build`、`cargo test --locked`、`git diff --check` 全部通过。

## 3. 总体架构与职责

```text
AI_LEARNING_POLICY.md       稳定规则与用户偏好
current_context.json        App 导出的动态学习状态
question_catalog.json       App 导出的候选题与题目指纹
recommendation.schema.json  AI 输出协议
codex-inbox                 AI 回传目录
SQLite                      事实、证据、状态和审计记录
```

### AI 负责

- 理解自然语言需求和当前训练目标。
- 从候选题目录中设计题组结构和顺序。
- 识别用户已经适应的考法，并选择下一种变化。
- 解释推荐理由、覆盖范围和成功标准。
- 根据完成结果提出下一轮训练假设。

### App 负责

- 生成状态快照和候选题目录。
- 验证题号、结构标签、难度、时间、重复度和题组约束。
- 记录实际作答、信心、耗时、批改和修复结果。
- 更新学习状态；AI 不能直接写入稳定掌握或 ELO。
- 将完成结果导出给下一轮 AI。

## 5. A：学习证据内核

### A1 统一作答事实

补齐 `attempts` 事实字段或旁表：

- `self_confidence`：作答前信心。
- `hint_level`：是否看提示及提示层级。
- `answer_change_count`：是否改答案。
- `duration_seconds`：有效作答时间。
- `outcome`：correct / partial / wrong / uncertain。
- `attempt_mode`：paper / review / pressure / challenge。
- `source_task_id`：来自哪个推荐题组。

验收：同一题的事实只记录一次，批改不得覆盖原始作答事实。

### A2 统一诊断模型

错误类别统一为：

- concept：概念/定理边界。
- strategy：方法选择/解题入口。
- modeling：建模和条件翻译。
- calculation：计算执行。
- speed：速度和时间管理。
- reading：审题。
- transfer：结构迁移失败。
- uncertain：证据不足。

批改必须保留最早错误、建议动作、验证题类型和置信度。

### A3 证据门控

- `uncertain` 不更新核心掌握状态。
- 低置信度诊断只作为待确认信号。
- 一次正确不关闭错题链。
- 看解析后正确的证据权重低于独立回忆。
- 压力模考结果不直接污染日常掌握度。

## 6. B：考点图谱

### B1 图谱结构

新增只读/可迁移的图谱资源或表：

- `knowledge_nodes`：概念、方法、结构、策略、迁移节点。
- `knowledge_edges`：前置、包含、易混淆、可组合关系。
- `knowledge_variants`：同一考点的考法变化维度。

节点字段：

```text
id, parent_id, subject, name, node_type, exam_frequency,
prerequisite_ids, common_errors, variant_dimensions, source
```

### B2 图谱初始化

第一批覆盖数学一高频分支：

- 极限与连续。
- 导数与微分。
- 一元函数积分。
- 微分方程。
- 多元函数微分。
- 二重积分。
- 无穷级数。
- 线性方程组、特征值、二次型。
- 概率基础、随机变量、数字特征、极限定理。

先保证结构可用，不追求一次性完美。未知节点必须标记 `unclassified`，不能假装已完成图谱标注。

### B3 图谱验收

- 每个推荐题组能指出目标节点。
- 每个节点能列出标准、条件变化、方法变化和迁移候选。
- 图谱缺失时推荐降级为普通候选，并明确提示“覆盖证据不足”。

## 7. C：题目指纹与新颖度

### C1 题目指纹

每题增加或生成：

```json
{
  "questionId": 155,
  "knowledgeNodeIds": ["integral.symmetry", "integral.substitution"],
  "representation": "function_expression",
  "conditionPattern": "symmetric_interval",
  "primaryMethod": "symmetry",
  "methodAlternatives": ["direct_calculation"],
  "combinationNodeIds": [],
  "role": "recognition",
  "difficulty": 2,
  "estimatedMinutes": 8,
  "examFrequency": "high",
  "structuredVariant": true
}
```

### C2 新颖度维度

题目之间比较以下维度，而不是只比较章节：

- 表面表示变化。
- 条件变化。
- 参数变化。
- 解题入口变化。
- 主方法变化。
- 知识点组合变化。
- 时间压力变化。

新颖度等级：same_template、numeric_change、condition_change、method_choice、structure_transfer、cross_topic。

### C3 阶段变化规则

- 暴露/基础：一次只改变一个因素。
- 巩固：同时改变两个因素。
- 迁移：允许多因素变化，但必须有中间证据。
- 综合：加入跨分支组合和时间限制。

## 8. D：AI 题组协议

### D1 稳定规则文件

新增 `AI_LEARNING_POLICY.md`，只存稳定规则：

- 只能从 `question_catalog.json` 选题。
- 必须说明目标节点、题目角色、考法变化、成功标准。
- 不得把一次做对判定为稳定掌握。
- 不得在没有结构化关系时称为迁移题。
- 不得超过时间预算 15%。
- 不得连续推荐三道同构题。
- 优先处理高信心错误和反复出现的错误。

### D2 输入快照

App 导出 `current_context.json`：

- 用户自然语言需求。
- 可用时间和当前精力。
- 考试目标和阶段。
- 分支状态：识别、方法选择、执行、迁移、保持。
- 最近错误和信心偏差。
- 到期复习节点。
- 最近题目和排除题目。
- 当前好友挑战/模考约束。

### D3 输出协议

`recommendation.schema.json` 至少包含：

- `taskId`、`schemaVersion`。
- `goal`、`estimatedMinutes`。
- `questionIds`、`questionRoles`、`order`。
- `coverage`：知识节点、题目映射、优先级。
- `noveltyPlan`：本组改变了哪些考法。
- `successCriteria`。
- `sourceEvidenceIds`。
- `excludedQuestionIds`。
- `confidence`。
- `fallbackPlan`。

兼容现有 `recommendedQuestionIds`、`recommendationReason` 字段。

## 9. E：推荐验证器

AI 输出进入训练前必须由 App 校验：

1. 题号存在且属于本地题库。
2. 题目未重复，或重复有明确复习理由。
3. 题目知识节点在目录中存在。
4. 题目角色与指纹匹配。
5. 覆盖节点达到用户需求中的最低集合。
6. 题组预计时间在预算范围内。
7. 难度和新颖度没有不合理跳跃。
8. 迁移题存在结构化关系。
9. 题组至少包含诊断或验证角色。
10. 题组不会重复最近已完成的同构题。

失败返回结构化错误，让 AI 重新生成；不得静默修正成另一组题。

审计表建议：`recommendation_runs`、`recommendation_items`、`recommendation_validation_errors`。

## 10. F：学习中心改造

### F1 第一屏：AI 训练入口

包含：

- 自然语言需求输入框。
- 快速模板：漏洞修复、扩大覆盖、方法辨析、迁移挑战、考场限时。
- 时间选择：15 / 30 / 45 / 60 / 90 分钟。
- 当前状态摘要：系统认为最危险的分支及证据。

### F2 题组预览

每组展示：

- 训练目标。
- 覆盖知识点树。
- 已适应考法。
- 本组新颖变化。
- 每题角色和预计时间。
- 成功标准。
- 推荐理由和证据。

每题支持：

- 勾选/取消。
- 替换同角色题。
- 查看题目详情。
- 加入自定义队列。
- 立即合流到 TodayView。

### F3 完成回顾

完成题组后展示：

- 哪些节点得到有效证据。
- 哪些节点仍未验证。
- 高信心错误。
- 低信心正确。
- 题组是否覆盖目标。
- 下一轮建议。

## 11. G：批改与复盘闭环

### G1 分层反馈

1. 结果和最早错误。
2. 要求用户解释关键步骤。
3. 方向性提示。
4. 完整解析。
5. 合上解析重新生成关键步骤。

### G2 修复链

```text
诊断 -> 原题重做 -> 相似题 -> 方法辨析 -> 变式迁移 -> 延迟回忆 -> 稳定关闭
```

每一步必须记录独立作答证据，失败时按错误类型回退，不无限增加债务。

### G3 间隔调度

- 即时修复：当次训练。
- 短期回忆：当天/次日。
- 中期保持：3～7 天。
- 长期保持：14～30 天。
- 迁移验证：与原题错开结构和时间。

## 12. H：自适应状态与推荐目标

每个知识节点维护：

- 识别概率。
- 方法选择成功率。
- 独立执行成功率。
- 迁移成功率。
- 限时成功率。
- 间隔保持率。
- 信心校准误差。
- 证据数量、质量和最近时间。

推荐目标函数：

```text
预期学习收益 =
修复概率 × 新增覆盖 × 迁移价值 × 考试相关性 × 证据可信度
÷ 预计耗时
```

扣除：同构重复、近期重复、难度跳跃和疲劳风险。

轨道动态调整：

- 高信心错误：提高修复和方法辨析。
- 标准题连续稳定：减少同构题，增加条件/结构变化。
- 迁移失败：回退一个阶段，不直接继续加难。
- 到期节点积压：增加保持题。
- 精力低：减少新颖度和限时压力。

## 13. I：AI 结果回传

每次题组完成生成不可变结果：

- 题目结果、信心、耗时、提示层级。
- AI/人工诊断和置信度。
- 实际覆盖节点。
- 未验证节点。
- 错误复发和阶段推进。
- 推荐是否被用户替换/跳过。

下一次 AI 只读取结果快照，不直接读取散乱数据库。

## 14. J：好友题组挑战

### 功能

- 从已做题、复盘题或模考题中勾选题目。
- 自定义题组标题和题量。
- 通过现有同步发送题号、标题、发送者和时间。
- 接收后校验本地题库，缺题明确提示。
- 一键载入 TodayView。
- 挑战结果单独记录，不改变正式 ELO。

### 隐私与边界

- 默认允许发送逐题题组，不发送草稿和数据库。
- 公开的是题组事实，不自动公开诊断报告。
- 好友挑战与正式竞技账分离。

## 15. K：心理负荷与停止规则

只管理训练状态，不做心理/医疗诊断。

输入：精力、专注、紧张、可用时间。  
输出：题组长度、新颖度、限时压力和反馈层级。

停止条件：

- 连续多题同一执行错误。
- 阅读和复盘质量明显下降。
- 已完成本轮最关键修复目标。
- 继续训练的预期收益低于恢复收益。

系统允许明确建议“今天停止”，漏练不清零，不制造补偿性刷题。

## 18. 测试与验收任务

### 单元和 Rust 测试

- 题号不存在时拒绝推荐。
- 题组超出时间预算时拒绝。
- 三道同构题连续出现时拒绝或要求替换。
- 无结构化关系时拒绝迁移角色。
- `uncertain` 和低置信度不更新状态。
- 一次正确不关闭错题链。
- 模考不改变日常掌握和 ELO。
- 推荐校验无任何数据库写入副作用。
- 迁移重复执行不重复插入。

### 前端测试

- TodayView 无新增干扰信息。
- 学习中心可展开、勾选、取消、替换和合流。
- 加入自定义队列失败时有反馈。
- 题组结果页覆盖状态正确。
- 题组缺题时显示明确错误。
- 好友题组同步后可开练。
- 全部 flag 关闭时回到 v1.5.5 行为。

### 人工验收场景

1. 标准题连续正确后，下一组出现条件变化而非换数字。
2. 高信心错误后，下一组优先方法辨析和修复。
3. 迁移失败后，系统回退一个阶段。
4. 用户只有 15 分钟时，题组仍保留诊断和验证闭环。
5. 用户说“今天只想覆盖知识点”，AI 按分支覆盖而不是按章节盲抽。
6. AI 输出错误题号时，App 拒绝并保留错误原因。
7. 好友发送已做题组，接收方可筛选并直接开始训练。

## 19. 发布门禁与回滚

每个阶段必须通过：

```bash
npm test
npm run build
cd src-tauri && cargo test --locked
git diff --check
```

发布前补充：

- 历史数据库只读回放。
- 旧版 flags 全关闭等价性测试。
- 推荐协议向后兼容测试。
- 好友快照 v2 兼容测试。
- 不触碰题库源、签名私钥和生产数据库写入。

出现以下情况立即关闭新 flag：

- 伪题号或题目内容不一致。
- 推荐重复率异常升高。
- 迁移题无结构证据。
- AI 低置信度结论污染掌握状态。
- TodayView 出现额外信息或性能回退。
- 好友同步将非公开数据带出设备。

## 20. 最终设计原则

```text
章节分类只负责定位范围。
考点图谱负责说明分支。
题目指纹负责说明考法。
AI 负责设计下一步变化。
App 负责验证题目和记录事实。
连续、独立、可追溯的证据才允许推进掌握状态。
```

1.6.0 的完成标志不是推荐了更多题，而是：

> 用户已经适应一种考法时，系统能识别这一点，主动选择下一种有价值的变化；用户做完后，系统知道哪些能力被验证、哪些仍然只是“看起来会”。

## 1. 产品目标

把当前的“AI 单次推荐”补齐为可重复运行的学习闭环：

```text
用户需求
→ App 根据现有分类树筛选候选题
→ AI 按本轮候选题识别考法
→ AI 生成结构化题组
→ App 校验题号、候选范围、顺序和时间
→ 用户在学习中心查看/调整/采用
→ TodayView 原样纸笔作答
→ App 记录真实作答和批改证据
→ 题组完成结果结构化导出
→ 下一轮 AI 读取上一轮结果
→ 输出“已验证 / 未验证 / 高风险 / 下一步动作”
```

本次目标不是建立新的题库分类体系，而是让这条闭环可解释、可恢复、可重复执行。

## 3. 本次必须完成的剩余任务

### P0-A：题组状态和失败恢复

#### A1. 完整状态模型

保持兼容现有状态，补齐必要状态：

```text
pending      已校验、未采用
active       当前正在训练
paused       被其他题组暂停
completed    全部题目完成
dismissed    用户拒绝
failed       校验或导入失败，可重试
```

如果不新增 `failed` 数据库状态，也必须提供等价的可追踪状态，不得只把错误文件静默丢进目录。

#### A2. 校验失败重试

在学习中心或收件箱提供：

- 错误原因；
- 原任务编号；
- 重新生成任务说明；
- 重试/重新导入入口；
- 重试不会创建重复批次。

错误题号、候选外题号、非法角色、coverage 越界、时间超限都必须能被用户看懂。

#### A3. 恢复与幂等

验收要求：

- 关闭 App 后重新打开，active 题组仍能恢复；
- 跳过或完成某题后，剩余顺序不改变；
- 撤销最后一次作答会清除对应题组完成绑定；
- 重复扫描同一回传文件不会重复写入；
- 重复点击采用、开始、刷新不会重复创建 attempt 或 batch item；
- 已完成或已拒绝题组不能再次进入训练。

### P0-B：学习中心题组工作台

#### B1. 逐题预览

AI 题组必须逐题展示：

- 题号和题干摘要；
- 题目角色：`diagnosis / method_choice / consolidate / integration / transfer / timed / challenge / review`；
- 预计耗时；
- 考法变化；
- 覆盖知识点或考法；
- 该题在本组中的顺序；
- 推荐理由。

已有推荐协议字段尽量复用，不要创建另一套 AI 题组协议。

#### B2. 题组编辑

用户在采用前必须可以：

- 勾选/取消单题；
- 保持至少一题诊断或验证题；
- 把单题加入自定义队列；
- 在同角色候选中替换题目；
- 查看替换后的时间预算和覆盖变化；
- 一键采用当前调整后的顺序进入 TodayView。

如果替换题没有可靠的结构关系，必须显示“结构证据不足”，不能伪造变式关系。

#### B3. 完成结果面板

完成题组后，在学习中心展示：

- 已验证考法；
- 仍未验证考法；
- 高风险复发考法；
- 高信心错误；
- 低信心正确；
- 目标是否完成；
- 下一步建议：修复、巩固、方法辨析、迁移或停止。

TodayView 不显示这些复杂信息，结果只放学习中心或复盘视图。

### P0-C：结果上下文完整化

现有 `*.result.context.json` 必须扩展为下一轮 AI 可直接使用的结构化事实。

每道题至少包含：

```json
{
  "questionId": 155,
  "questionRole": "method_choice",
  "result": "correct",
  "outcome": "correct",
  "durationSeconds": 120,
  "selfRating": 3,
  "attemptMode": "paper",
  "evidenceSource": "self_report",
  "sawSolution": false,
  "gradingVerdict": "correct",
  "earliestError": null,
  "errorTags": [],
  "coverageStatus": "verified"
}
```

其中：

- `sawSolution` 不允许根据猜测填写；没有证据时写 `null`；
- `gradingVerdict`、`earliestError`、`errorTags` 只使用已确认批改结果；
- `coverageStatus` 只能是 `verified / unverified / high_risk / uncertain`；
- 一次正确不能自动写成 `verified`，除非有足够独立证据；
- uncertain 或低置信度不能推进稳定状态。

结果文件还必须包含：

- 题组目标；
- AI 推荐理由；
- 本组 coverage；
- noveltyPlan；
- successCriteria；
- 本组是否完成目标；
- 未验证考法列表；
- 下一轮建议动作。

### P0-D：下一轮 AI 任务闭环

新的 `create_learning_task` 上下文必须带上最近完成题组的结果文件，并在 prompt 中明确要求 AI 回答：

1. 哪些考法已经有有效独立证据；
2. 哪些只是一次正确，不能算稳定；
3. 哪些考法仍未验证；
4. 哪些考法出现高信心错误或复发；
5. 是否回退到修复题；
6. 是否应该改变条件、表示、方法入口或知识组合；
7. 本轮题组每道题分别承担什么角色；
8. 本轮成功标准和失败后的 fallback。

AI 只能从 App 的候选题中选择题号。

### P0-E：好友题组记录边界

好友题组继续保持：

- 可以发送已经做过的题；
- 接收后校验本地题库；
- 缺题明确提示；
- 一键进入 TodayView；
- 不改变正式 ELO。

本次补充：

- 记录好友挑战的 `challengeGroupId` 或等价来源标识；
- 让好友题组作答记录可以与普通自定义队列区分；
- 不公开草稿、详细批改报告或私有诊断内容。

## 5. 推荐实现顺序

1. 先读现有 schema 和批次状态，写迁移而不是重建数据库；
2. 先完成 A：失败状态、重试、恢复和幂等；
3. 再完成 B：逐题预览、勾选、同角色替换、自定义队列和结果面板；
4. 再完成 C：把批改诊断和题目角色合并进 result context；
5. 最后完成 D/E：下一轮 AI prompt 和好友挑战来源绑定；
6. 写测试后再做视觉调整；
7. 不要先做大规模重构或新建抽象层。

## 6. 必须新增或补充的测试

### Rust

- 错误题号无法创建 recommendation batch；
- 候选外题号无法创建 recommendation batch；
- 非法角色、coverage 越界、时间超限会失败；
- 失败任务可以重试且不会重复插入；
- active 题组重启后仍可恢复；
- 题组完成后每个 item 绑定真实 attemptId；
- result context 包含题目角色、结果、耗时、自评和诊断字段；
- 重复导出 result context 幂等；
- 撤销作答会清除题组完成绑定；
- 好友挑战来源不进入正式 ELO；
- uncertain/低置信度不会推进 verified 状态。

### 前端

- AI 生成题组按钮默认可用；
- 训练模板可以填入需求；
- AI 题组逐题预览正确；
- 勾选/取消题目后数量、时间和顺序正确；
- 同角色替换失败时有明确提示；
- 加入自定义队列失败时有反馈；
- 采用后进入 TodayView 且不新增复杂信息；
- 完成题组后显示已验证/未验证/高风险；
- 失败任务显示原因并能重试；
- 好友题组可以开练但不显示私有诊断。

## 7. 固定人工验收场景

1. AI 返回不存在的题号：App 拒绝，显示原因，不进入队列。
2. AI 返回候选范围外题号：App 拒绝，保留任务上下文。
3. 用户取消 AI 题组中的一题：时间、覆盖和顺序即时更新。
4. 用户替换一题：只能从同角色候选中选择。
5. 用户完成一组题：学习中心显示真实结果，而不是只显示完成数量。
6. 高信心错误：下一轮 AI 优先安排修复或方法辨析。
7. 标准题连续正确：下一轮出现条件、表示或方法入口变化，而不是只换数字。
8. 迁移证据不足：AI 不得标记 transfer，App 不得替其背书。
9. 关闭 App 后重开：活动题组和剩余顺序保持。
10. 好友发送题组：接收后能开练，记录与正式 ELO 分离。

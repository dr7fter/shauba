## 2. P0：必须先修（否则数据或主环不可信）

### P0-1 压力模拟对主观题是空转，且会留下脏会话

证据：

- 提交只把 `selected.join('')` 当答案。主观题没有选项，实库 7 条压力作答 `user_answer` 全空。
- 批改 prompt 用「当前题的 `selected` + `sessionDurations`」拼学生答案；压力路径**从不写入** `sessionDurations`，于是所有题都变成「未作答」。见 `src/App.tsx` `generateGradingPrompt`。
- `complete_pressure_session` 固定返回 `"questions": []`，后端答案作废。
- 批改 JSON 与 `AGENTS.md` 的 inbox 协议是两套；粘贴成功后「加入错题本」只 `console.log`，**不** `record_attempt`，不进 SRS / 复盘 / 今日进度。
- 退出不收口，实库已有两条 `ongoing` 会话（16 题队列），无法恢复。
- 总用时用 `Date.now()` 直接渲染，没有 interval，界面上的钟是假的。

**修复方向（二选一，必须先定）**：

1. **推荐**：0.9.1 先把入口藏起来或打「未完成」标记，避免再写脏数据；清理 `ongoing` 会话。
2. 若保留：改成「闭卷纸笔整组」——不收屏幕答案，复用已有 `create_codex_batch_task` + `codex-inbox`；选择题可记选项；主观题只记用时+草稿任务；确认后才写 `attempts`。禁止再发明一套粘贴 JSON。

### P0-2 「查看答案」双入口，计时和选择题判定会分叉

- 主按钮走 `reveal()`：结算时长、选择题自动判定。
- 页脚「查看答案」只 `setRevealed(true)`，**不**结算、**不**自动判定。
- 空格快捷键走 `reveal()`，和页脚按钮不一致。

必须合并为同一个 `reveal()`。

### P0-3 昨日对比用错日期

`daily_log` 的 `days` 按时间**正序**（最早在 `[0]`）。  
`TodayView` 却写着「`days[0]` 是今天，`days[1]` 是昨天」。  
实库 `[1]` 是 2026-08-15（16 题），不是昨天 08-19（26 题）。成就卡「比昨天多/少」是错的。

应改为按本地今天取 `date === today` 的前一天，或直接用 `get_daily_trend`。

### P0-4 顶栏连续天数写死 0

`get_streak` 已存在，Insights 能显示 3 天。顶栏仪表盘却是 `streak: 0 // 暂时设为 0`。用户会以为连续性丢了。

### P0-5 题库只在空库导入，`content_hash` 不比对

- 启动仅当 `questions` 为 0 才 `import_library`。
- 文件名写死 `all_questions_20260813.json`。
- 每题都存了 `content_hash`，之后从不比较、不提示、不增量更新。

题库源一更新，App 会继续用旧题干/旧答案批改。这是数据正确性风险。

### P0-6 工程源与发布不一致

- 运行中的 0.9.0 主要在未提交工作区。
- 设置文案仍是 v0.7.0。
- vNext 需求/验收文件被删，没有 0.9 的权威清单（本计划补上）。

0.9.1 前应提交或明确丢弃工作区，备份文案改成当前版本，恢复或替换被删文档。

## 3. P1：实用性问题（每天都会碰到）

1. **三套计时互不相干**：顶栏专注钟、题内钟、压力总用时。顶栏钟不写入 attempts。只保留题内钟作为作答证据；顶栏钟要么删，要么标明「不计入统计」。
2. **每题弹出成就卡**：打断「看答案 → 自评 → 下一题」。里程碑（5/10/20）可以留，常规题改为底栏轻提示。
3. **闪击战 vs 压力模拟**：两个「高压考试」入口。闪击战是 15 分钟 4 道选择题式打分；压力模拟声称闭卷+Codex。用户分不清。应合并叙事，或闪击战降为题库里的小游戏。
4. **主观题可只打流畅度就提交**：`determineAttemptEvidence` 在未选 outcome 时记 `uncertain`，成就卡却显示「❌ 错误」。必须先选「做对/部分/做错/不确定」才能「记录并继续」。
5. **复习间隔文案撒谎**：界面「评分 1 → 明日，其它 → 3 天」；设置里实际是 3/5/15/30。按 `review_intervals` 显示真实下一复习日。
6. **奖励账本无入口**：表和 2 条记录还在，游戏 UI 已删。要么做只读「奖励账本」，要么在设置里说明已停用，不要留幽灵数据。
7. **今日完成数含 uncertain**：bootstrap 的 `today_done` 是 `COUNT(*)`。不确定诊断会虚增进度。应与 Insights 一样排除 uncertain。
8. **小窗主操作在折页下**：840×620 先看到题干和「查看答案」，「我已完成」在答案面板里，要滚才看见。主 CTA 应钉在题干区。
9. **字体未打包**：token 写了 Inter / 霞鹜文楷 / JetBrains Mono，安装包无字体资源。没装这些字体的机器会回落到雅黑/宋体。发布说明不得写成「字体系统全面焕新已完成」，除非打包或明确回退栈。
10. **Codex 协议分裂**：inbox JSON（可用、已有 13 条 confirmed）vs 压力模式粘贴 JSON（无测试、无入库）。只保留 inbox。
11. **debug 日志**：提交路径有 `🎯 准备显示成就卡片` 等 `console.log`，正式版去掉。
12. **变式题搜索过粗**：`startTagPractice` 用标签当题库全文检索，匹配不到就空转。应走考点路径或 `variant_queue`。

## 6. 建议节奏（按结果，不按功能清单）

### Sprint A · 0.9.1 可信修复（优先，约 1–2 天）

目标：用户再打开 App，数字是对的，不会再写脏压力数据。

- 隐藏或阻断压力入口；清理 `ongoing` 会话
- 合并 `reveal()`
- 修正昨日对比与顶栏 streak
- 备份文案改为 0.9.0
- 去掉成就卡 debug log
- 主观题强制选判定
- 提交 0.9 源码或打 `v0.9.0-wip` 标记，避免安装包与 Git 脱节

**完成标准**：验收文件 AC-P0 全 PASS。

### Sprint B · 主环压实（约 2–3 天）

目标：每天只做一件事时不迷路。

- 今日页：到期 → 薄弱修复 → 新题，默认顺序写清楚
- 单一作答钟；顶栏钟降级或删除
- 成就卡改为里程碑-only
- 复习间隔文案与 SRS 一致
- `today_done` 排除 uncertain
- 题库 hash 变化提示（先提示，不自动覆盖作答）
- Codex 只走 inbox；进展页行动卡可一键进入对应队列

**完成标准**：用实库走完「到期 1 题 + 错题变式 3 题 + 1 次草稿批改」无数据分叉。

### Sprint C · 压力模拟重做或删除（约 2 天，可延后）

仅当 A/B 完成后：

- 选择题：记录选项 + 用时
- 主观题：不收屏幕答案，生成整组草稿任务
- 结果经 inbox 确认后写 attempts
- 会话可恢复、可放弃、进入主备份
- 补 Rust/前端测试

若做不到，就从 UI 删除，避免 0.10 再堆一个第三套考试模式。

## 7. 建议的产品原则（写进后续开发约定）

1. **屏幕选择不是纸笔证据。** 主观题默认 uncertain，除非用户或 Codex 明确判定。
2. **一条作答记录必须同时有 outcome、fluency、evidence_source、duration。** 新模式不准只写自己的旁路表。
3. **AI 只进 `codex-inbox`。** 禁止第三种 JSON。
4. **今日页的每个按钮都要能回答：这题做完去哪。** 闪击战/压力/专注/公式如果不能接 SRS，就不要和「开始训练」并列。
5. **文档跟版本走。** 删验收文件等于删合同。

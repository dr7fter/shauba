## 一、体系架构总览

### 评分分层的核心决策

**AI 打证据分，内核当裁判**：
- Codex 通过提示词（带锚点 rubric）从草稿给出六维分数与 rating，分布守门靠提示词约束 + 0-2 范围校验；
- 跨时间的量（衰减聚合、ELO 结算、段位）由确定性内核处理，LLM 无状态、会漂移，不能承担记账职责。

**评分回退链**（前后端一致，`六维合成 > Codex rating > 特征曲线`）：
1. 有六维分数 → HLTV 线性合成
2. 无六维但有 Codex rating → 直接采信（clamp 0-2）
3. 都没有 → 特征曲线合成（对错 × 0.55 + 自评 × 0.25 + 速度 × 0.2，四次方上尾）

### HLTV 六维线性评分（`src-tauri/src/services/rating.rs`）

```
P = 0.42×解决 + 0.18×严谨 + 0.18×影响力 − 0.22×错误代价
rating = clamp(0.30 + 0.016×P) × 难度系数(0.94–1.10)
```

- 影响力 = 0.6×strategyInsight + 0.4×methodUse，techniqueLevel≥4 加 5
- 错误代价 = 结果基分（对0/部分40/错100）×0.75 + 超时占比×0.25
- 锚点：部分正确 ≈ 0.93、普通全对 ≈ 1.36、六维全优 ≈ 1.55、做错 0.4-0.5
- 权重常量集中在 `rating.rs` 顶部（`HLTV_*`），**配平验证靠洞察页分布直方图**

### 完美平台天梯机制（`src-tauri/src/lib.rs` ELO 常量区）

| 参数 | 值 | 位置 |
|---|---|---|
| 定级起点 ELO_START | 1400（C 段） | lib.rs `ELO_START` |
| 定级期 K | 60（前 10 次结算） | `ELO_K_CALIBRATION` |
| 常态 K | 25 | `ELO_K` |
| 期望公式 | `0.70 − 0.10×(掌握度−1) − 2.5×(难度−1)`，clamp [0.30, 0.78]，review +0.06 | `settle_elo` |
| 连胜动量 | 连续≥3 同向 → K×1.15 | `ELO_MOMENTUM_*` |
| 晋级保护 | 升段后 3 次结算免负分 | `ELO_PROMOTION_PROTECTION` |
| 段位表 | D<1000, D+1000, C1201, C+1401, B1601, B+1801, A2001, A+2201, S≥2401 | `rating.rs rank_band_index` + 前端 `utils.ts WANMEI_RANKS`（**两处需同步改**） |
| 赛季软重置 | 向 1400 收敛 25%，`season_reset` 事件 | `SEASON_RESET_PULL` |

万位→千位刻度迁移：`migrate_schema` 中 `elo_wanmei_migrated` 标记，`新 = 1400 + (旧−10000)×0.1`。

### 数据落库（attempts 表新增列）

`difficulty_multiplier / technique_level / dim_rigor / dim_computation / dim_modeling / dim_method_use / dim_speed / dim_strategy_insight`——**目前只有批量批改（batch confirm）会写入**，日常单题无六维走回退链。

相关表：`elo_events`（attempt_id/question_id/delta/rating_after/performance/expected/session_id/reason，reason ∈ match|codex_review|season_reset）、`season_history`。

## 四、已知边界

1. 六维数据只有批量批改产生，HLTV 公式与 WE 评分需积累批量数据后 fully 生效
2. ELO 结算挂在 `record_attempt_row` 单一入口，所有模式（含 review）统一结算
3. 段位表双处维护（Rust + TS），改段位必须两处同步
4. `photo/`、`.claude/`、`.zcode/` 已 gitignore 但保留在磁盘
5. 前端测试几乎为零（仅 `tests/evidence_model.test.js`），回归靠 cargo test + tsc + build

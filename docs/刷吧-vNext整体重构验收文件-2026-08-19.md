# 刷吧 vNext 整体重构验收文件

> 对应需求：docs/刷吧-vNext整体重构需求报告-2026-08-19.md  
> 基线版本：v0.6.0  
> 验收对象：刷吧桌面 App vNext 候选版本（RC）  
> 编制日期：2026-08-19  
> 文档状态：待执行  
> 产品边界：独立的数一桌面刷题 App；题库源目录只读；不连接 Obsidian、拾遗录、云同步或社交服务。

## 1. 验收目标

本文件用于判断 vNext 是否真正完成了“纸笔作答 → 可信诊断 → 最小修复 → 间隔重测”的主闭环。  
验收不以“页面能打开”或“构建成功”为充分条件，而以以下结果为准：

1. 用户打开 App 后能在 30 秒内知道今天先做什么。
2. 没有点选屏幕选项的纸笔作答不会被系统自动记为错误。
3. 正确性、流畅度、自评、AI 判断和证据来源彼此分离且可追溯。
4. AI 诊断能在两次点击内转为修复任务或变式重测。
5. 到期复习进入今日任务，而不是被隐藏在独立入口。
6. 奖励、掌握度、时长和统计在重启后仍与真实记录一致。
7. 在四档窗口尺寸下，主要操作可见、可读、可达，不出现中文竖排或横向滚动。
8. 迁移、备份、恢复不会修改题库源文件，也不会静默丢失旧作答。

## 2. 范围与不在范围内

### 2.1 本次必须验收

- 今日、题库、复盘、进展四个一级入口及其路由。
- 今日任务单、统一目标、统一计时和会话恢复。
- 纸笔训练四阶段：理解题目、纸笔作答、对照判断、修复动作。
- 作答证据模型、旧数据兼容、异常时长处理。
- Codex 单题/批量诊断回传、确认、修复队列和变式重测。
- 到期复习、复盘时间线、掌握证据和可执行洞察。
- 奖励账本、领取幂等、真实纪录和游戏化开关。
- 考试日期配置、主题、字号、减少动效和基本可访问性。
- 自动化检查、视觉回归、数据库迁移、备份恢复和题库源哈希保护。

### 2.2 明确不作为本次完成条件

- 账号体系、云同步、好友排行、公开社区。
- 将 App 改成电子草稿板或强制用户输入完整推导。
- 修改 E:\考研资料\题库-大观园 中的 JSON、图片或目录结构。
- 用“AI 已分析”替代用户确认，或把低置信度结果强行写成正确/错误。
- 仅新增入口、图表、徽章或动画而没有改善主闭环。

## 3. 验收前置条件

### 3.1 环境

- Windows 桌面环境，使用与发布目标一致的 Tauri 构建产物。
- 使用独立的验收数据库副本；不得直接在用户生产库上做迁移试验。
- 题库源目录 E:\考研资料\题库-大观园 设为只读，验收前生成 JSON 与图片哈希清单。
- 验收使用真实题库 ID 或专门的测试夹具；不得为了测试而改写题库源数据。
- 清空或显式标记动态时间、随机题目和本地时钟，避免截图回归误报。

### 3.2 最小测试夹具

至少准备以下可重复夹具：

| 夹具 | 目的 |
|---|---|
| 客观题 A：纸上作答，不点击屏幕选项 | 验证不能自动记错 |
| 客观题 B：点击正确选项 | 验证 digital_answer |
| 客观题 C：点击错误选项 | 验证错误判定 |
| 主观题 D：自评 4，但无人工/AI 结果 | 验证不能由流畅度推断正确 |
| 主观题 E：人工确认 partial/uncertain | 验证结果与证据来源分离 |
| Codex 批改单题与批量任务 | 验证最早错误、置信度和回传 |
| 重复领取同一契约/宝箱 | 验证奖励幂等 |
| 含 1 条 duration_seconds > 1800 的历史库 | 验证异常时长不污染洞察 |
| 含未完成会话的数据库副本 | 验证继续、放弃和查看队列 |
| 可恢复与损坏的备份文件 | 验证恢复前备份和失败保护 |

### 3.3 结果标记

- PASS：满足 Given/When/Then，且有可复核证据。
- FAIL：不满足条件；P0 失败直接阻断发布。
- BLOCKED：环境或前置数据不可用，不能当作通过。
- WAIVED：只有在负责人、日期、风险和补偿方案都记录后才可使用；P0 不允许无条件豁免。

## 4. 发布门槛

### 4.1 P0：恢复信任（发布阻断项）

以下项目全部通过，才允许进入公开可用的 vNext RC：

| 验收域 | 通过标准 | 证据 |
|---|---|---|
| 样式与布局 | 洞察、设置、判定反馈、详情笔记样式完整；无浏览器原生表单回退 | 四档截图、视觉回归报告 |
| 纸笔证据 | 未点选屏幕选项时不自动写入 wrong | 数据库记录、录屏 |
| 结果分离 | 主观题不会用 fluency_rating 推断 outcome | 单元测试、记录 JSON |
| 目标与计时 | 今日只有一套目标；会话计时与题目时长口径一致 | 配置与重启前后数据 |
| 奖励真实性 | EXP、契约、宝箱和纪录均来自持久化账本；重复领取不重复到账 | reward_events 查询、重启测试 |
| 考试日期 | 日期由用户设置或明确的官方配置提供，未配置时不显示伪精确倒计时 | 设置页截图、边界测试 |
| 历史时长 | 超过 1,800 秒的旧记录不进入趋势、战报和毅力值；原始记录不被静默改写 | 迁移前后查询、洞察截图 |
| 数据与题库 | 迁移失败停止写入并可恢复；题库源哈希不变 | 哈希对比、恢复日志 |
| 工程基线 | 建立可回退的版本基线，发布产物与源码版本一致 | Git 提交/标签、版本清单 |

### 4.2 P1：主流程成立（vNext 核心功能门槛）

- 一级导航收束为今日、题库、复盘、进展；设置位于次级入口。
- 今日页生成唯一任务单，默认顺序为到期复习 → 薄弱修复 → 新覆盖。
- 未完成会话可继续、放弃或查看队列，不静默丢失。
- AI 确认后自动生成最小修复卡和修复队列，最多两次点击开始训练。
- 复盘时间线串联作答、AI 待确认、修复任务、到期重测和已攻克。
- 进展页首屏最多三条行动建议，每条都有依据、置信度、预计耗时和开始按钮。
- 掌握结论显示证据等级、样本量和来源，不把不同来源伪装成单一正确率。

### 4.3 P2：品质与扩展（最终发布门槛）

- 1440×900、1280×720、1024×768、840×620 四档窗口均通过布局验收。
- 浅色、暖纸、深色、跟随系统主题可用；支持字号档位、关闭音效、减少动效。
- 所有纯图标按钮具备 aria-label；颜色状态同时有文字或图标。
- 前端按路由或领域拆分，构建产物有明确 chunk 预算；不保留未解释的大 chunk 警告。
- 每日纸笔任务包、真模考、公式间隔复习、考试阶段自适应按已确认的优先级交付；未交付不得伪装成已完成。

## 5. Given / When / Then 验收用例

### 5.1 P0 用例

#### AC-P0-UI-01 样式完整性

- Given：打开洞察、设置、题目判定反馈和题目详情。
- When：在全新缓存和已有数据两种情况下刷新页面。
- Then：摘要卡、趋势图、科目卡、表单分组、判定状态和详情笔记均有设计系统样式；不得出现未排版的原生输入、丢失间距或文字重叠。

#### AC-P0-UI-02 顶栏可用

- Given：窗口宽度依次为 1440、1280、1024、840 像素。
- When：打开今日页和训练页。
- Then：页面标题、当前会话时间、通知、个人入口可见；中文不被压成竖排；主要 CTA 不被挤出或遮挡；不依赖横向滚动。

#### AC-P0-EVID-01 纸笔客观题不误判

- Given：选择客观题 A，用户只在纸上完成，不点击屏幕选项。
- When：点击揭示答案并提交“做对/部分正确/做错/无法判断”中的任一结果。
- Then：系统使用 manual_confirmed 或 self_report 记录用户结果，不得因为屏幕选项为空而写入 wrong；页面说明证据来源。

#### AC-P0-EVID-02 屏幕选项判定

- Given：客观题 B 或 C 在屏幕上选择答案。
- When：揭示答案。
- Then：系统可给出 digital_answer 建议，但用户仍可修正结果；最终记录包含 outcome、evidence_source 和时间，不覆盖人工修正。

#### AC-P0-EVID-03 主观题结果与流畅度分离

- Given：主观题 D，用户选择流畅度 4，但没有人工确认或 Codex 结果。
- When：提交作答。
- Then：fluency_rating 为 4，outcome 为 uncertain 或待确认状态；不得自动写入 correct，且不得进入正确率分子。

#### AC-P0-DATA-01 今日目标单一真相

- Given：设置中配置每日题数或分钟目标，打开今日页和个人进展。
- When：完成、暂停、重启 App。
- Then：今日任务、进度、契约和奖励使用同一目标与同一时长口径；不存在两个互相矛盾的“今日目标”。

#### AC-P0-DATA-02 会话计时边界

- Given：开始、暂停、恢复并结束一题，期间关闭并重新打开窗口。
- When：查看题目时长、会话时长和今日总时长。
- Then：三者按文档定义一致；单题新记录限制在 1–1,800 秒，并标记是否发生截断。

#### AC-P0-REWARD-01 奖励账本幂等

- Given：同一契约或宝箱产生唯一 event_id。
- When：连续点击领取、刷新页面、重启 App，再次触发同一事件。
- Then：账本只有一条该 event_id；EXP 只增加一次；等级、战报和显示余额重新计算后仍一致。

#### AC-P0-REWARD-02 空纪录不虚构

- Given：新用户没有闪击战、模考或连对纪录。
- When：打开游戏化/个人进展区域。
- Then：显示“尚未产生纪录”等空状态；不得出现非零的默认成绩。

#### AC-P0-EXAM-01 考试日期可信

- Given：用户尚未配置考试日期。
- When：打开 App。
- Then：不显示伪精确的剩余天数；提示去设置或显示“未配置”。

- Given：用户配置有效考试日期并重启。
- When：查看倒计时。
- Then：倒计时使用该日期，并在跨日、修改日期和清空日期后正确更新。

#### AC-P0-DURATION-01 异常时长隔离

- Given：数据库中存在 duration_seconds > 1800 的历史记录。
- When：打开洞察、周报、战报和毅力值。
- Then：异常记录不进入聚合；页面显示排除数量和原因；原始作答记录仍可查看和人工修正。

#### AC-P0-SOURCE-01 题库源只读

- Given：记录验收前题库 JSON 与图片的哈希。
- When：执行迁移、导入、推荐、训练和备份恢复全流程。
- Then：验收后哈希完全一致；任何功能不得删除、重命名、重写或压缩题库源文件。

#### AC-P0-ENG-01 失败可回退

- Given：使用验收数据库副本执行迁移。
- When：人为注入迁移失败或磁盘写入错误。
- Then：停止后续写入，保留失败日志，自动提供恢复前备份；恢复后旧版本数据可读。

### 5.2 P1 用例

#### AC-P1-TODAY-01 今日任务单

- Given：存在到期题、薄弱标签和未完成会话。
- When：打开今日页。
- Then：首屏给出唯一推荐任务、预计题数/分钟、优先级理由和一个主 CTA；默认顺序为到期复习 → 薄弱修复 → 新覆盖。

#### AC-P1-TODAY-02 调整任务的后果可见

- Given：用户把今日题数从默认值调整为更高或更低。
- When：确认调整。
- Then：系统同步更新预计耗时、复习债务影响和任务结构；不再生成第二套契约目标。

#### AC-P1-SESSION-01 会话恢复

- Given：会话中途关闭 App，队列包含未完成题目。
- When：再次启动。
- Then：提示“继续 / 放弃 / 查看队列”；继续后题目来自当前数据库，索引、已完成题和计时不静默丢失。

#### AC-P1-REVIEW-01 复盘时间线

- Given：存在普通作答、到期题、AI 待确认和修复任务。
- When：打开复盘。
- Then：按时间线展示各状态；uncertain 明确标注“未计入正确率和作答记录”；每项可直接回到题目或任务。

#### AC-P1-AI-01 AI 批改确认

- Given：Codex 返回单题或批量结果。
- When：用户打开收件项并确认。
- Then：保存 summary、earliestError、errorTags、weaknessTags、confidence 和证据来源；无法确定的步骤保留 uncertain，不得猜测。

#### AC-P1-AI-02 诊断转修复

- Given：一条已确认的 partial、incorrect 或高价值 uncertain 诊断。
- When：点击“现在修复”或“加入今日末尾”。
- Then：系统生成最小修复卡和近迁移题队列；从诊断到开始第一道修复题不超过两次点击。

#### AC-P1-REVIEW-02 到期重测

- Given：某知识点已有错误诊断和复习日期。
- When：到期后完成重测。
- Then：重测结果进入同一证据链，更新下次复习时间；不能仅凭“看过解析”提升掌握等级。

#### AC-P1-INSIGHT-01 洞察可行动

- Given：存在重复错误、覆盖缺口或复习债务。
- When：打开进展页。
- Then：首屏最多三条建议；每条包含依据、置信度、预计耗时和开始按钮，开始按钮能打开对应训练队列。

#### AC-P1-MASTERY-01 掌握证据可解释

- Given：同一知识点存在自评、客观判定、Codex 和间隔重测记录。
- When：查看掌握度。
- Then：显示证据等级、样本量和来源；至少能区分“独立做对”和“间隔后仍能做对”，不输出无法解释的小数精度。

### 5.3 P2 用例

#### AC-P2-RESP-01 四档窗口

- Given：窗口尺寸为 1440×900、1280×720、1024×768、840×620。
- When：依次访问今日、训练、复盘、进展、设置。
- Then：无主要内容被遮挡，无横向滚动；小于 1050 像素侧栏收为图标栏，小于 960 像素训练队列变抽屉、答案面板移到题目下方。

#### AC-P2-A11Y-01 键盘与读屏

- Given：仅使用键盘和可访问性树。
- When：完成打开任务、揭示答案、选择结果、提交和返回。
- Then：焦点顺序合理；所有纯图标按钮有 aria-label；状态不只依赖颜色；关闭按钮和弹窗有可读名称。

#### AC-P2-THEME-01 主题与动效

- Given：切换浅色、暖纸、深色、跟随系统，并开启减少动效/关闭音效。
- When：进入训练、复盘和进展页面。
- Then：主题在重启后保持；文本和公式对比度可读；减少动效后不播放非必要动画；关闭音效后无答题反馈音。

#### AC-P2-PERF-01 构建体积

- Given：执行生产构建。
- When：检查构建输出和首屏加载。
- Then：无 TypeScript 构建错误；大 chunk 有明确预算和拆分理由；路由级代码不会在首屏加载全部游戏化与报表模块。

## 6. UI 四档窗口验收矩阵

每个尺寸至少保存今日页、训练页（答案未揭示/已揭示）、复盘页、进展页和设置页截图。截图命名建议为：
evidence/vnext-<date>/<AC-ID>/<width>x<height>-<state>.png。

| 尺寸 | 必查布局 | 必查交互 |
|---|---|---|
| 1440×900 | 完整侧栏、任务单、题干与答案区层级 | 主 CTA、结果选择、修复卡 |
| 1280×720 | 顶栏不拥挤；题干和按钮不被压缩 | 揭示答案、提交、切换复盘 |
| 1024×768 | 侧栏收缩；卡片不重叠 | 打开队列抽屉、返回上级 |
| 840×620 | 训练队列抽屉；答案面板位于题干下方 | 仅键盘完成一次最短训练流程 |

统一判定：

- 中文标题、按钮和提示不得出现竖排或单字换行。
- 不得出现必须横向滚动才能点击的主要操作。
- 主要按钮最小高度 36 px，首要 CTA 42–46 px。
- 正文不低于 14 px；题干默认约 24 px，行高约 1.8。
- 动态倒计时、随机题目和本地时间在截图比对中使用屏蔽区，不得以此掩盖结构性错位。

## 7. 数据、迁移与证据验收

### 7.1 作答记录最低字段

每条新作答至少可读取以下字段，旧字段继续兼容：

~~~text
outcome: correct | partial | wrong | uncertain
evidence_source: digital_answer | self_report | codex | manual_confirmed | legacy
fluency_rating: 1..4
confidence: 0..1 | null
duration_seconds: 1..1800
session_id: string
diagnosis_id: string | null
~~~

要求：

- outcome 与 fluency_rating 独立存储。
- uncertain 不进入正确率分子，不写入“已完成正确复习”的奖励条件。
- legacy 只表示来源未知，不得补造 digital_answer 或 codex。
- 迁移采用加法式字段扩展；失败时原库可回退。

### 7.2 AI 回传

- 单题、批量和推荐回传必须校验 schemaVersion、taskId、questionId 和结果枚举。
- 题目 ID 无法验证时不得生成推荐结果。
- 草稿不足时，批量结果不得凭空补齐未上传题目。
- 回传确认前可以编辑或拒绝；确认后才进入掌握证据和修复队列。
- confidence 不足时必须显示不确定并保留人工确认入口。

### 7.3 备份与恢复

- 启动自动创建滚动备份，至少保留最近 7 份和每周 4 份。
- 恢复前先备份当前库，并显示恢复来源、时间和校验结果。
- 恢复成功后随机抽查旧作答、到期日、AI 收件项、奖励事件和设置。
- 恢复失败时不覆盖当前可用数据库，并给出下一步操作。

## 8. 自动化与工程质量门槛

在验收环境执行以下命令，并将完整输出保存到验收证据目录：

~~~text
npm run lint
npm run build
Set-Location src-tauri
cargo test --locked
~~~

通过标准：

- npm run lint 退出码为 0；vNext RC 不得新增 lint 警告，最终发布目标为 0 警告。
- npm run build 退出码为 0；TypeScript 不得有错误；任何大 chunk 警告必须有预算、原因和后续拆分计划。
- cargo test --locked 全部通过，失败或被跳过的测试不得以“环境问题”直接视为通过。
- 必须补充前端行为测试命令（例如 npm run test 或等价命令），至少覆盖 AC-P0-EVID-01、AC-P0-REWARD-01、AC-P1-SESSION-01 和迁移回退；命令不存在即不能声称 vNext 核心完成。
- 视觉回归必须覆盖四档窗口和五个主要页面；动态区域通过屏蔽规则排除，结构性差异不能豁免。

## 10. “不算完成”的明确边界

出现以下任一情况，即使 npm run build 通过，也不能宣布 vNext 核心完成：

- 纸笔客观题未点选选项仍被记为 wrong。
- 主观题只选流畅度 3/4 就被写成 correct。
- AI 标签能展示但没有确认、修复任务或变式重测入口。
- 今日目标、契约、手动计时和题目时长仍各自统计。
- 奖励只存在组件状态或 localStorage，重启丢失或重复领取可叠加。
- 名人堂或战报用虚构非零纪录填充空状态。
- 考试日期仍由硬编码或近似日期提供。
- 异常历史时长继续污染洞察，或迁移静默改写原始记录。
- 只在一个大窗口看起来正常，840×620 或 1024×768 出现遮挡、竖排或主要操作丢失。
- 题库源 JSON/图片哈希发生变化，或测试直接修改题库源文件。
- 只有截图好看但没有自动化测试、迁移回退测试和备份恢复证据。
- 只新增游戏化、图表或入口，没有让用户更快完成“今天该做的下一步”。

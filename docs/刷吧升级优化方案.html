2.2 根因：期望基线被钉死在 0.50，而表现分的中位数在 1.30

我在 lib.rs:5254 与 rating.rs:291-296 找到了确切的公式，并把你的真实数据代进去验证：

// lib.rs:5254 —— ELO 结算
let score = (performance / 2.0).clamp(0.0, 1.25);

// lib.rs:5183 —— 期望公式
expected = 0.50 + 0.04 × (mastery − 2) − 0.25 × (difficulty − 1)
         → clamp[0.20, 0.80]

// 代入你的真实数据（mastery=2, difficulty=1.0 为最常见情形）
expected ≈ 0.50   ⇒   ELO 零点 = performance 1.00
但你 performance 的实际分布中心 = 1.30
⇒ score = 0.65 > expected 0.50  ⇒  delta = K × 0.15，恒为正

为什么表现分会系统性偏高？因为 68% 的题目没有 AI 批改，走的是 rating.rs 的默认维度值。我把默认值代进合成公式：

// rating.rs —— 六维缺失时的兜底默认值（outcome = "correct"）
Cast   = 100.0                      // 写死：做对就是 100
Impact = 0.6×65 + 0.4×65   = 65.0   // 默认 strategy/method = 65
KAST   = 0.5×75+0.3×75+0.2×75 = 75.0   // 默认 rigor/comp/modeling = 75
Pacing = 100.0                      // 正常耗时即满分

composite = 0.38×100 + 0.22×65 + 0.20×75 + 0.20×100
          = 38 + 14.3 + 15 + 20 = 87.3

rating = 0.26 + 0.0125 × 87.3 = 1.351
一句话根因

「做对了但没人看过过程」这道题，被系统自动判定为 1.35 分——而 1.35 在你的锚点表里是「巧解秒杀」。

你实际正确率只有 51%，却有 66% 的作答拿到「优秀」以上评级。评分尺子的零点，从一开始就没对准。

7算法修复：精确的改法

这一节给出可直接落地的参数与代码级建议。所有改动都在 rating.rs 与 lib.rs 的常量区，不涉及架构变动。

7.1 修复一：把期望基线从「固定 0.50」改为「自适应锚点」

当前问题的本质是：期望是一个写死的常量，而表现分的分布是浮动的。只要分布中心偏离 0.50，ELO 就会单向漂移。最稳健的解法是让基线跟随用户自己的近期水平。

// lib.rs 常量区 —— 新增
const ELO_ANCHOR_WINDOW: usize = 30;      // 近 30 次结算
const ELO_ANCHOR_MIN_SAMPLES: usize = 10; // 样本不足时用固定基线
const ELO_ANCHOR_BLEND: f64 = 0.70;      // 自适应锚点权重（其余给固定基线）

// 计算：取近 N 次 performance 的中位数作为「你当前的正常水平」
fn adaptive_anchor(conn: &Connection) -> f64 {
    let mut scores: Vec<f64> = /* 近 ELO_ANCHOR_WINDOW 次的 performance/2 */;
    if scores.len() < ELO_ANCHOR_MIN_SAMPLES {
        return ELO_EXPECTED_BASE;              // 0.50，定级期行为不变
    }
    scores.sort_by(|a, b| a.partial_cmp(b).unwrap());
    let median = scores[scores.len() / 2];
    // 与固定基线混合，防止分布整体漂移时锚点自己也漂走
    ELO_ANCHOR_BLEND * median + (1.0 - ELO_ANCHOR_BLEND) * ELO_EXPECTED_BASE
}

// 结算时改为：
let expected = adaptive_anchor(conn)
             + ELO_EXPECTED_MASTERY_STEP  * mastery_offset
             - ELO_EXPECTED_DIFFICULTY_STEP * diff_offset;
为什么用中位数而不是均值

你的表现分里有 21.3% 落在 <0.8（崩盘区），均值会被这些极端值拉偏；中位数更能代表「你当前的正常水平」。 混合 30% 的固定基线则是为了防止锚点自己也跟着漂走——如果完全自适应，长期退步的人会感觉不到退步。

7.2 修复二：让「做错」真正付出代价

即使加了自适应锚点，还需要保证做错必定扣分。当前公式下，做错时 score ≈ 0.285、expected ≈ 0.47，理论 delta 是 −1.85，但实际有 48% 的做错题在涨分——因为 Pacing 极高（秒答）或难度系数压低了期望。

// 在 settle_elo 结算末尾加一道硬闸
let mut delta = k * (score - expected);

// 结果闸门：做错必须扣分，且不得低于一个下限
if outcome == "wrong" || outcome == "incorrect" {
    delta = delta.min(-ELO_WRONG_FLOOR);       // ELO_WRONG_FLOOR = 1.0
}
// 做对必须涨分（防止难题难度系数把期望压到超过表现分）
if outcome == "correct" {
    delta = delta.max(ELO_CORRECT_FLOOR);      // ELO_CORRECT_FLOOR = 0.5
}

7.3 修复三：放大难度杠杆，让难题真的有吸引力

当前 -0.25 × (dm - 1) 在 dm ∈ [0.94, 1.10] 范围内只能产生 ±0.04 的影响，几乎无效。要让「攻克难题收益大」这个设计意图真正生效：

// lib.rs:5185 —— 难度步长放大一个数量级
const ELO_EXPECTED_DIFFICULTY_STEP: f64 = 0.25;  // 现：影响 ±0.04
const ELO_EXPECTED_DIFFICULTY_STEP: f64 = 2.50;  // 改：影响 ±0.40

// 效果对照（mastery=2 时）：
//   最简单题 dm=0.94 → expected = 0.50 + 0.15 = 0.65  （做对收益变小）
//   标准题   dm=1.00 → expected = 0.50                （不变）
//   最难题   dm=1.10 → expected = 0.50 - 0.25 = 0.25  （做对收益大增）

配合自适应锚点后，「做对难题」与「做错简单题」的收益差会从当前的约 3 分拉开到 10 分以上，ELO 才真正具备区分度。

重算后你的 ELO 大概率会下跌 100 分左右。这不是退步，是把虚高的水分挤掉。建议在设置页提供「重新校准天梯分」入口，并明确告知用户这是修正而非惩罚。

阶段三解耦：让代码撑得住下一次进化建议 2–3 周

功能已经很多了，再往 13156 行的单文件里加东西，边际成本会急剧上升。这一阶段不改任何用户可见行为，纯粹是工程投资。

  1. B1 同步命令改 async（74 个）——纯机械改动，风险最低，收益最直观。可分批：先改聚合查询类（洞察、导出、题库搜索），再改简单 CRUD。
  2. B2 / B3 学习中心与启动导入的性能修复。
  3. B7 补索引，并把 substr(attempted_at,1,10)=? 改为范围比较。
  4. B4 统一错误类型 + F7 前端错误层（这两项必须联动做）。
  5. F5 TodayView 拆分——最大的一项结构性债务，建议放在 B1 之后、趁热打铁。
  6. F10 补前端测试：优先覆盖 utils 评分层与 normalizeAnswer。

阶段四增强：把「刷题工具」变成「备考系统」持续迭代

前三个阶段解决「现有能力的可信度」，第四阶段才是补能力。以下按提分性价比排序，而非实现难度。

  1. 每日投入看板：把「今天练了多久 / 距离目标 2.5 小时还差多少」放到今日页顶部。你现在日均 66 分钟，缺的不是功能，是一个提醒。
  2. 科目覆盖仪表盘：三科进度条对照考研分值占比，让「概率 0 题」这种结构性风险自己跳出来，而不是藏在数据页里等人发现。
  3. 套卷模拟：当前全是散题。考研是 3 小时 23 道题的连续作战，需要完整的限时套卷模式 + 分题时间分配建议。
  4. 错题二刷强制化：错题不复习就不出新题（或大幅降权），把「一刷不回头」从默认行为变成需要主动绕过的行为。
  5. AI 批改覆盖率提升：当前仅 32%。可做「草稿拍照 → 批量批改」的一键流程，把收件箱从 49 条的量级提上去。
  6. 考前倒计时与节奏规划：距考试天数 → 剩余可练题量 → 每日配额，把「我该练多少」变成系统给出的答案而非每天的纠结。

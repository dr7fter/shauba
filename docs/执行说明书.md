有，而且我建议把这部分单独设计成一次“学习闭环升级”，不要继续零散地增加几个统计字段。

当前刷吧已经有：

- 批改；
- Rating/ELO；
- 六维能力；
- 错误标签；
- 薄弱知识点；
- 压力训练报告；
- 题目历史；
- 今日训练。

但这些模块还没有完全串成：

```text
做题
→ 批改
→ 识别问题
→ 更新画像
→ 推荐下一题
→ 安排复习
→ 验证是否真正掌握
```

我建议把后续学习功能升级为一个独立的“学习闭环引擎”。

# 一、总体方案：建立学习状态引擎

不要把用户画像理解为一张静态雷达图，而要拆成两层。

## 1. 能力画像

相对稳定，反映用户长期能力：

- 概念理解；
- 计算严谨性；
- 解题速度；
- 建模能力；
- 方法选择；
- 考场策略；
- 各章节知识掌握度；
- 题型迁移能力。

## 2. 学习状态

实时变化，反映用户当前是否需要干预：

- 最近是否连续犯错；
- 是否正在遗忘；
- 是否会做但速度慢；
- 是否只会原题，不会变式；
- 是否自评与实际表现不一致；
- 是否已经复习过但再次失败；
- 是否长时间没有接触某个知识点。

最终画像不能只显示：

```text
积分 1600
Rating 1.12
计算能力 72
```

而应该能回答：

```text
你现在最需要复习什么？
为什么推荐这道题？
你是不会，还是会但不稳定？
这个知识点是真的掌握，还是只记住了原题？
今天应该练多少？
```

# 二、批改系统升级方案

## 2.1 从“判对错”升级为“定位最早错误”

批改结果建议统一为以下结构：

```ts
type LearningDiagnosis = {
  verdict: 'correct' | 'partial' | 'incorrect' | 'uncertain'
  earliestError: string | null
  errorTags: string[]
  weaknessTags: string[]
  confidence: number

  correctnessScore: number
  methodScore: number
  rigorScore: number
  speedScore: number
  transferScore: number

  rating: number
  advice: string
  nextAction: 'move_on' | 'review' | 'retry' | 'learn_method' | 'manual_check'
}
```

核心不是增加更多分数，而是让每个分数都有明确用途。

例如：

```text
最终答案正确，但中间步骤存在严重跳步：
结果：correct
严谨性：62
迁移能力：未知
建议：安排一道同方法变式题
```

或者：

```text
最终答案错误，但最早错误只是符号笔误：
结果：partial
概念掌握：较高
计算严谨性：下降
建议：做短时限计算复核题
```

## 2.2 引入“批改置信度门控”

AI 批改不应无条件修改用户画像。

建议规则：

| 批改置信度 | 处理 |
|---|---|
| 0.90 以上 | 正常更新画像 |
| 0.75～0.90 | 更新，但降低权重 |
| 0.60～0.75 | 只生成建议，不改变核心掌握度 |
| 低于 0.60 | 标记 uncertain，要求重新批改或人工确认 |

这样可以避免一次错误识别导致：

```text
用户明明会做
→ AI 误判不会
→ 画像下降
→ 推荐大量简单题
→ 用户体验越来越差
```

## 2.3 增加批改一致性检查

批改完成后由确定性逻辑检查：

- verdict 与 result 是否冲突；
- 错题 Rating 是否超过限制；
- `incorrect` 是否给出了明确错误断点；
- `correct` 是否存在严重错误标签；
- 建议是否为空；
- 置信度是否在 0～1；
- 同一批题是否全部给中庸分；
- 速度评分是否符合耗时；
- Rating 是否和题目难度、实际用时匹配。

AI 负责提供证据，内核负责决定是否采纳。

这和现有项目的原则一致：

```text
AI 打证据分，确定性内核当裁判。
```

# 三、打分系统建议：拆分用途，不要让一个 Rating 负责全部事情

目前最容易出现的问题是：

```text
一个 Rating 同时表示正确率、能力、速度、题目表现、长期水平。
```

建议拆成五类指标。

## 3.1 结果分

只回答：

```text
这道题做得对不对？
```

例如：

- 正确；
- 部分正确；
- 错误；
- 不确定。

## 3.2 掌握度变化

只回答：

```text
这个知识点掌握得怎么样？
```

掌握度不应被一题完全改变。

建议：

```text
新知识点：单题影响较大
已经稳定的知识点：单题影响较小
连续失败：逐步下降
连续成功且有变式：逐步上升
```

## 3.3 熟练度

回答：

```text
会不会做得快？
```

区分以下情况：

| 表现 | 判断 |
|---|---|
| 做对且快 | 熟练 |
| 做对但慢 | 掌握但不流畅 |
| 做错且快 | 概念或瞄准问题 |
| 做错且慢 | 方法未掌握或计算黑洞 |
| 原题做对、变式做错 | 记忆性掌握 |

## 3.4 迁移能力

回答：

```text
换一种问法后还能不能做？
```

这是当前学习系统最值得补充的一项。

一个知识点只有在以下情况都通过后，才应标记为稳定：

1. 原型题做对；
2. 相似题做对；
3. 变式题做对；
4. 间隔几天后仍做对；
5. 限时状态下仍能做对。

## 3.5 HLTV Rating

继续保留，但定位为：

```text
本次题组表现质量
```

不要直接把 Rating 当成永久能力。

因此建议区分：

```text
matchRating：本次比赛表现
skillMastery：知识点掌握度
fluency：熟练度
transfer：迁移能力
ladderElo：长期天梯水平
```

这样可以避免：

```text
一次超常发挥让画像虚高
一次状态不好让画像崩掉
```

# 四、画像系统升级方案

## 4.1 知识点状态模型

每个知识点建议至少维护：

```ts
type SkillState = {
  skillTag: string

  mastery: number
  confidence: number
  fluency: number
  transfer: number
  forgettingRisk: number

  attempts: number
  correctCount: number
  recentWrongCount: number
  consecutiveCorrect: number
  consecutiveWrong: number

  lastAttemptAt: string | null
  lastCorrectAt: string | null
  nextReviewAt: string | null

  dominantErrors: string[]
  sourceQuestionIds: number[]
}
```

例如：

```text
定积分换元：
掌握度 78
熟练度 51
迁移能力 42
遗忘风险 67
主要问题：上下限变化、符号检查
```

这比单纯显示：

```text
定积分：78 分
```

更有指导意义。

## 4.2 错误画像

错误标签不能只用于显示，还要形成统计：

```text
计算笔误
概念边界
方法选择
条件遗漏
审题失误
超时
步骤跳跃
答案表达
```

统计：

- 发生次数；
- 最近发生时间；
- 连续发生次数；
- 出现在哪些知识点；
- 是否在限时环境下更严重；
- 是否已经通过变式训练修复。

然后生成可读结论：

```text
你最近 7 天的主要问题不是不会做，而是：
会选择方法，但在变上限和符号转换处容易出错。
```

## 4.3 画像要区分“不会”和“没稳定”

建议增加四种状态：

```text
未接触
初步掌握
掌握但不稳定
稳定掌握
```

不要把一次做对直接标记为掌握。

推荐升级条件：

```text
至少 3 次有效练习
至少 1 次间隔复习
至少 1 次变式题
至少 1 次限时题
```

# 五、推荐系统升级方案

推荐不能只是：

```text
哪里错得多，就推荐哪里。
```

这样会造成用户一直刷同一类简单题。

## 5.1 推荐分数建议

每道候选题可以计算：

```text
推荐优先级 =
遗忘风险
× 知识点薄弱度
× 考试重要度
× 题目匹配度
× 预期学习收益
× 近期复习必要性
```

再减去：

```text
重复惩罚
过难惩罚
近期已做惩罚
同类型堆积惩罚
```

不用一开始追求复杂机器学习，先用确定性规则就足够可靠。

## 5.2 推荐分成四条轨道

每日题目不要全是错题。

建议默认比例：

```text
修复：40%
巩固：25%
迁移：20%
挑战：15%
```

### 修复题

针对最近最早错误和核心薄弱点。

### 巩固题

针对已经学会但不稳定的知识点。

### 迁移题

同一方法换条件、换问法、换场景。

### 挑战题

用于保持上限和考场适应能力。

如果用户近期连续失败，自动降低挑战比例。

如果用户连续稳定成功，增加迁移和挑战比例。

## 5.3 每道推荐题必须显示理由

推荐卡片不能只写：

```text
推荐练习
```

应该显示：

```text
推荐理由：
你在最近 3 次定积分题中有 2 次出现上下限处理错误，
这道题用于验证该问题是否已经修复。
```

用户需要知道：

```text
为什么是这道题，而不是另一道题。
```

## 5.4 推荐结果必须可验证

推荐之后记录：

```ts
type RecommendationLog = {
  questionId: number
  reason: string
  targetSkills: string[]
  expectedGoal: string
  recommendedAt: string
  completedAt?: string
  outcome?: string
}
```

这样以后可以知道：

```text
推荐是否真的有效？
推荐后用户是否改善？
哪些推荐理由经常失败？
```

# 六、计划安排方案

建议增加“动态计划”，不要做死板的日历。

## 6.1 每日计划结构

根据用户当天可用时间，自动生成三段：

```text
热身
核心修复
迁移验证
```

例如 45 分钟：

```text
热身：5 分钟
核心修复：20 分钟
综合训练：15 分钟
错题回忆：5 分钟
```

90 分钟则增加：

```text
限时小组赛
```

## 6.2 每天最多三个主要目标

不要给用户铺满十几个知识点。

每天最多：

```text
1 个主修复目标
1 个巩固目标
1 个迁移目标
```

例如：

```text
主目标：修复二重积分换序
巩固目标：保持矩阵特征值
迁移目标：混合题中识别方法
```

## 6.3 根据表现实时调整计划

训练过程中动态调整：

| 结果 | 后续动作 |
|---|---|
| 做错且概念错误 | 降低难度，先讲方法，再做基础题 |
| 做错但属于笔误 | 安排短时限复核题 |
| 做对但超时 | 安排同类限时题 |
| 做对且很快 | 进入变式或综合题 |
| 原题对、变式错 | 标记为未迁移 |
| 连续两次不确定 | 暂停自动升级，要求重新批改 |

计划不应因为用户一次失败就全部重排，否则会让系统显得不稳定。

# 七、错题复习升级方案

错题不应该是一个永久列表，而应是一个状态机。

## 7.1 错题状态

```text
新错题
→ 已诊断
→ 待首次复习
→ 首次复习通过
→ 变式验证
→ 间隔复习
→ 稳定掌握
```

如果后续再次错：

```text
稳定掌握
→ 重新暴露
→ 重新进入复习队列
```

## 7.2 复习不能只让用户重做原题

建议每次错题复习分四层：

### 第一层：回忆

不看解答，回答：

```text
这道题考什么？
第一步应该做什么？
最容易在哪里错？
```

### 第二层：重做

重新完整作答。

### 第三层：变式

同一个知识点，改变：

- 条件；
- 数值；
- 问法；
- 解题入口；
- 题目顺序。

### 第四层：限时迁移

混入其他章节中，检查用户能不能主动识别方法。

## 7.3 复习间隔

第一版可以使用：

```text
1 天
3 天
7 天
14 天
30 天
```

但不要机械固定。

根据结果调整：

- 做对且快：延长间隔；
- 做对但慢：保持当前间隔；
- 做对但不确定：不延长；
- 再次做错：退回较短间隔；
- 概念错误：重新进入方法学习阶段。

## 7.4 错题要有“关闭条件”

不能让错题无限存在。

建议满足以下条件后标记为稳定：

```text
原题通过
相似题通过
变式题通过
间隔复习通过
限时题通过
```

否则只能叫：

```text
暂时通过
```

# 十、建议的实施优先级

## P0：先修复批改数据契约

目标：

- 统一批改字段；
- 增加置信度；
- 增加 `nextAction`；
- 校验 Rating 边界；
- 区分错误、不会、超时、笔误；
- 让批改结果可以被后续模块消费。

## P1：建立知识点状态

目标：

- 每个知识点有掌握度；
- 区分掌握、不稳定、遗忘；
- 记录错误模式；
- 记录最后练习时间；
- 不再只看总分和六维雷达。

## P2：接入推荐系统

目标：

- 每题显示推荐理由；
- 修复、巩固、迁移、挑战四条轨道；
- 记录推荐效果；
- 避免重复刷同类题。

## P3：接入计划系统

目标：

- 根据时间自动生成今日计划；
- 每天最多三个重点；
- 根据训练结果动态调整；
- 计划未完成时自动顺延，而不是直接丢弃。

## P4：重做错题复习

目标：

- 错题状态机；
- 间隔复习；
- 变式题；
- 限时迁移；
- 稳定掌握判定。

## P5：画像和报告升级

目标：

- 画像解释；
- 画像变化原因；
- 训练收益；
- 本周进步；
- 下周重点；
- 推荐是否有效的反馈。

# 十一、最重要的产品原则

## 1. 不要被一次答题结果牵着走

一次错题不能直接证明不会。

一次正确也不能直接证明掌握。

## 2. 不要只追求分数变高

真正重要的是：

```text
能否迁移
能否保持
能否限时完成
能否减少同类错误
```

## 3. 推荐必须可解释

每一条推荐都要能回答：

```text
为什么现在推荐？
它要修复什么？
完成后如何判断有效？
```

## 4. AI 不能直接修改长期画像

AI 的诊断必须经过：

```text
置信度检查
规则校验
历史证据融合
```

再更新知识点状态。

## 5. 学习计划不能压垮用户

如果计划过多，用户会产生：

```text
每天都没完成
→ 计划失去可信度
→ 不再使用
```

宁可每天给三个准确目标，也不要给二十个泛泛任务。

---

# 十二、我最推荐的第一版目标

如果要控制范围，我建议第一版先实现以下五件事：

```text
1. 批改结果结构化
2. 知识点掌握状态
3. 每日推荐三题
4. 错题间隔复习
5. 报告中生成下一步行动
```

先不要急着做：

- 复杂机器学习；
- 自动生成大量新题；
- 复杂日历；
- 全量知识图谱；
- 过度细分的能力分数；
- 复杂社交学习排行榜。

对刷吧来说，最有价值的不是再加一张图，而是让用户每天明确知道：

```text
今天练什么
为什么练
```

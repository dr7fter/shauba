## 一、现状：三个层次的问题

### 1. 硬编码假数据（最严重，不是审美问题）

| 位置 | 写死的内容 | 性质 |
|---|---|---|
| 逐题推导轴 Step I / II / III | 「辅助分量设式与前置分离」「偏导化简」等文案 | 与本题完全无关的固定文案 |
| 步骤分数标签 | `+4分` / `+2分` / `-6分` | 固定数字 |
| 朱砂眉批扣分列表 | `-4 核心定理拓扑前置条件破坏` / `-2 最终结论计算错误` | 固定两行 |
| 实得分数 | `12/12`、`6/12`、`0/12` | 按 verdict 硬映射，非真实得分 |
| 评分细则表（audit tab） | `+4 / -4 / -2` | 固定三条 |
| 左栏成绩卡 | `FIRST CLASS · 甲等上`、`稳定击败 94.2% 同卷考生` | 编造 |
| fallback 值 | `132` 分、`93.5%` | 编造 |
| 失分扣除 | `wrongCount * 6` | 凭空乘算 |

**后果**：学员侧会拿假分数做判断；开发者侧知道是假的，整个报告的可信度归零。
这一条不解决，改 UI 只是换个壳。

### 2. 信息架构：有价值的数据被埋了

- 真正有用的字段：`earliestError` / `betterSolution` / `errorTags` / `duration` / `dimensions` / `rating`
- 它们被塞在：三栏工作台 → 中栏「常春藤正卷」→ 双栏批注流 → 右侧眉批卡，四级深度
- 「六维证据」默认是折叠抽屉，要手动点开
- 两套视图（工作台 / 长卷通览）功能高度重叠，维护成本翻倍

### 3. 缺的东西（一份批改报告最该有、现在完全没有）

| 缺项 | 说明 |
|---|---|
| **耗时 vs 首次的对比** | 项目里最硬的判据（降到 1/3 以下才算掌握），报告里一次都没出现 |
| **错误路径固化检测** | 复习比首次快还错 = 最危险信号，报告里不可见 |
| **与上一组的趋势对比** | 只有单点正确率，看不出变好还是变差 |
| **错误类型聚合** | 现在是 per-question 流水账，没有按 `errorTags` 归并 |
| **耗时 vs 预算 / 止损线** | 已有量化结论（5′ 软提醒、8′ 硬止损），完全没用上 |
| **可执行的下一步** | 只有 per-题的收藏 / 加练按钮，没有一份排序过的行动清单 |
| **复习排期落地** | 没有把结果写回 `progress.next_review_at` 的展示 |

### 4. 视觉

三套风格互相打架：常春藤羊皮纸（serif + PAPER I SECTION B + MASTER RESOLUTION）
＋ CS 电竞（DONK 👑 / CLUTCH ⚡ / KAST 防白给指数）＋ mono 角标。
另有硬编码颜色散落在 JSX 里（`text-[#2d6a4f]`、`bg-[#fef2f2]` 等）。

## 二、三份示范的取舍

| | 方案 A 结构化体检单 | 方案 B 断点工作台 | 方案 C 极速速览 |
|---|---|---|---|
| 组织单位 | 指标 → 断点聚合 → 逐题 → 行动 | **断点**（一级单位） | 表格行 |
| 一屏信息量 | 中（需轻度滚动） | 中（需滚动） | **高（8 题不滚动）** |
| 最擅长 | 全局判断 + 收尾行动 | **深挖一个断点并当场处理** | 每天 12 题的快速扫 |
| 弱项 | 单题细节要展开 | 全局数字偏弱（塞在侧栏） | 深度不够，适合看不适合改 |
| 每日复盘 | ✅ | ⚠ 略重 | ✅✅ |
| 大组批改（20+ 题） | ⚠ | ✅ | ✅✅ |

**推荐：A + B 融合，C 作为「紧凑模式」开关。**

- 顶部固定 A 的判定条 + 指标条（5 秒看完）
- 主体用 B 的断点卡（因为断点是唯一需要「处理」的东西）
- 已掌握 / 无需处理的题折叠成 C 里那样的表格行，塞在底部
- 提供「紧凑 / 详细」切换，紧凑模式就是 C 的表格

## 三、落地清单（按优先级）

### P0 · 删假数据（不做这个，改 UI 无意义）

1. 删除 Step I/II/III 硬编码三步推导轴，改为：有 `earliestError` 就渲染成单张「最早断点卡」，没有就不渲染
2. 删除硬编码的 `+4 / +2 / -6`、`-4 / -2` 扣分明细、评分细则表
3. 删除 `12/12`、`6/12`、`0/12` 硬映射 —— 后端没有真实得分字段，就不要显示得分；
   要么后端补 `score` / `maxScore`，要么只显示判定（对 / 半对 / 错）
4. 删除 `FIRST CLASS`、`94.2%`、`132`、`93.5%`、`wrongCount * 6`
5. 删除全部装饰性大写英文（`STUDENT DERIVATION TRAIL` / `MASTER RESOLUTION` / `PAPER I SECTION B`）

### P1 · 补真数据（新增展示，需要后端或查询配合）

1. **耗时对比**：每题拿 `attempts` 里同一 `question_id` 的首次 `duration_seconds` 与本次对比，
   标注「真掌握（≤1/3）」/「假掌握（>1/3）」/「固化（变快仍错）」
2. **错误类型聚合**：按 `errorTags` 归并，显示次数 + 涉及题号 + 次数排序
3. **趋势对比**：与上一组（同 `sourceTaskId` 组别或最近一次批改）比正确率、均题耗时
4. **耗时预算**：单选 2.7′ / 主观 5.2′（或按 difficulty：d1 3.2′ / d2 4.7′ / d3 6.4′），
   超出显示红条，>8′ 打「超止损线」标记
5. **固化检测**：`复习耗时 < 首次耗时 且 结果仍为 wrong` → 打「错误路径固化」红标

### P2 · UI 与交互

1. **合并双视图**：删掉 workbench / overview 两套，改为「紧凑 / 详细」一个开关
2. **六维雷达默认展示**（不再是抽屉），缺证据的维度显示「未采集」而不是不画
3. **统一视觉**：一套中性浅色 + 一个强调色；红=错 / 琥珀=半对 / 绿=对；
   硬编码颜色全部收进 CSS 变量
4. **底部行动清单**：按优先级排 3–5 条，每条带预计耗时和「一键排入明日」
5. **键盘**：保留 J/K 翻题，补 `E` 展开全部、`Esc` 关闭

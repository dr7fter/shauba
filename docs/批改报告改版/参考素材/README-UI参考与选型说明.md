## 一、搜到的参考素材与可复用点

### 1. 学习分析仪表盘（教育数据报告）

来源：`educaweb.org/pages/resources/edtech/assessment-data-and-reporting.html`、
`Smart Learning Environments`（LearningViz、多模态 LAD 两篇）

可直接搬的 6 条铁律：

| 原则 | 原文要点 | 对应到刷题报告 |
|---|---|---|
| **先报异常，再报均值** | "A class average of 68% tells a teacher nothing they can act on" | 顶部放「路径固化 2 题」而不是「正确率 50%」 |
| **按目标统计，不按题统计** | Mastery by objective，不是 by question | 断点按「错误类型/方法入口」聚合，不按题号流水账 |
| **颜色只代表一件事** | 单一量表，不混用红=低 / 红=注意 | 红只用于「错 / 固化 / 超止损」 |
| **每个数字都能点回证据** | Clicking a red cell should open the actual responses | 断点卡必须带题号 + 首次/复习耗时 |
| **一屏、不滚动、不需培训** | 两分钟内读完 | 折叠已掌握的题 |
| **耗时先于分数报警** | Time-on-task often flags a struggling learner before the score does | 8′ 硬止损进报告 |
| **小样本不说趋势** | 3 questions on fractions is not enough | #1982 同题 4 次 → 标记「小样本」而非硬伤 |

> 这一批是 5 份示例里 **E5 临床体检单** 的主要来源：指标 + 参考区间 + 异常箭头 + 医嘱。

### 2. 赛后战绩板（CS:GO / Leetify 一类）

来源：`counterstrike.fandom.com/wiki/Scoreboard`、
`readkong.com`（CS:GO player performance dashboard 需求文档）

| 战绩板语汇 | 迁移到刷题 |
|---|---|
| K / D / A | 攻克 / 失守 / 半对 |
| ADR（每回合均伤） | 有效耗时占比（耗时里有多少是有效推导） |
| MVP 星标 | 本组最难且独立做对的题 |
| **Wrong-doings 分组** | 错误类型聚合（闪光自己 / 烧到烟上 → 换元方向选反 / 幂函数留在 u 位） |
| **Highlights（正向行为）** | 已固化、大幅提速、硬啃 d3 —— 不只报错 |
| 准星热力图 | **失分位置热力**：断点落在「设式 / 换元 / 运算 / 结论」哪一步 |
| 经济局 / 半买 | 止损线分档（&lt;2′ / 2–5′ / 5–8′ / 8–15′ / &gt;15′） |

> 这是 **E4 赛后数据板** 的来源，也呼你要的「CS 竞技游戏的惊喜感与游戏性」。

### 3. 中文错题本 / 学情报告

来源：`aistory.com.cn/docs/guide/wrong-questions.html`、`ai6s.net`（鸿蒙错题本·横线笔记本风）、
`lanlanwork.com`（错题本卡片信息效用评估）

| 模式 | 要点 |
|---|---|
| 顶部四卡 | 累计错题 / 薄弱知识点 / **已攻克** / 总正确率——「已攻克」比「正确率」更能体现真进步 |
| 左薄弱知识点、右错题列表 | 按正确率升序排，点知识点过滤右侧 |
| 两种视图 | 列表（紧凑快扫）↔ 卡片（逐题细看） |
| 展开三层 | **答案对比（左红右绿）** → AI 错因分析 → 变式题 |
| 错因统计条 | 彩色圆点 + 错因名 + 数量，横向滚动 |
| 反面教训 | 「掌握度」字段放进错题本没意义——错题本永远不可能 100%，别显示 |

> 支撑 **E2 分叉对照**（答案双栏 diff）和 **E3 行动清单**（已攻克优先）。

## 二、5 份示例的定位

| 示例 | 隐喻 | 一级单位 | 一屏能回答的问题 | 强项 | 弱项 |
|---|---|---|---|---|---|
| **E1 断点工单** | Linear / issue tracker | **断点**（不是题） | 我有几个断点、各是什么状态 | 状态机（未处理→观察中→已固化）可流转；否定式规则直接写在卡上 | 全局感弱，看不到"今天整体怎么样" |
| **E2 分叉对照** | 阅卷 diff | **题**（我的路径 vs 标准路径） | 我这一步到底走岔在哪 | 双栏并排，差异点一眼可见；适合单题深挖 | 8 题铺开太长，只适合展开单题 |
| **E3 行动清单** | 待办 / 作战计划 | **动作** | 接下来 3 件事做什么 | 收尾即可执行，零思考成本 | 没有诊断过程，无法判断"为什么" |
| **E4 赛后数据板** | CS 战绩 / Leetify | **题（计分板行）** | 今天打得怎么样、MVP 和失误各是什么 | 游戏化最强、密度高、有正向反馈（高光/失误并列） | 隐喻重，严肃备考时可能嫌吵 |
| **E5 临床体检单** | 化验单 | **指标** | 哪些指标异常、异常到什么程度、怎么治 | 参考区间 + H/L 箭头让数字有标尺；**医嘱**闭环最强 | 逐题细节被压平，需要下钻 |

## 三、选型建议

**不要只选一份**——这 5 份不是皮肤差异，是**三层不同的问题**：

```
E5 指标层（现在怎么样、严不严重）
  ↓ 点"路径固化 2"
E1 断点层（断点是什么、怎么拦截）
  ↓ 点某断点的题号
E2 对照层（我走岔在哪一步）
  ↓ 处理完
E3 行动层（接下来做什么）
```

**推荐落地组合**：

1. **主视图 = E5 + E1**：顶部 6 项指标带参考区间（这是"清晰整洁"的关键——数字有标尺就不用猜），
   主体是断点工单卡（按严重度排序，已固化的折叠）。
2. **单题下钻 = E2**：点断点 → 双栏 diff 看具体岔路。
3. **每日快扫 = 计分板表格**（E4 中段，去掉深色战报头）：每天 12 题 3 秒扫完。
4. **E4 的深色战报头单独做成「本组战报分享图」**：不进日常阅读流，只用于阶段复盘/发呆时激励。
   这样游戏化有地方放，又不干扰备考时的专注。

**"清晰整洁"的三条硬约束**（落代码时必须守）：

- 一屏只留 **1 个默认展开的长文本**——就是最早断点。标准解法、我的路径一律折叠。
- 已掌握/已固化的题**不展开**，压成一行表格。
- 每个数字后面必须有**对照物**（参考区间、首次耗时、止损线），否则删掉这个数字。

## 四、数据字段对照（确保示例不是空想）

| 示例元素 | 数据来源（现已存在 / 需补） |
|---|---|
| 判定（攻克/半克/失守） | `attempts.outcome` ✅ |
| 首次 / 本次耗时 | `attempts.duration_seconds` ✅（有脏数据需清洗） |
| 耗时比值 0.46 / 0.08 | 需后端补：按 question_id 取首次 attempt 对比 |
| 真掌握判据 ≤1/3 | 纯前端计算 ✅ |
| 断点文本 | `codex_inbox.payload_json → batchAttempts[].earliestError` ✅ |
| 错误标签 | `errorTags` / `weaknessTags` ✅ |
| 标准解法 | `betterSolution` ✅ |
| 六维 | `dimensions` ✅ |
| **失分位置热力** | ⚠️ 需批改侧新增 `error_step` 字段（设式/换元/运算/结论） |
| **参考区间** | ⚠️ 需按考点累积历史基线（当前只有全局止损线 n=180） |
| 变式题推荐 | ⚠️ 需题库侧相似题检索 |

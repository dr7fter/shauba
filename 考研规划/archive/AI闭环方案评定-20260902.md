## 三、三个设计层面的否决（即使不考虑你的偏好）

### 3.1 把 AI 调用编译进 Rust = 架构倒退

- **提示词是迭代最快的资产**。我 9/1 一天改了 5 次 skill/MEMORY。在 Rust 里改提示词 = 改一次编译一次，这个仓库 `src-tauri/` 有 68663 个文件。
- **红线风险**：AGENTS.md 第一条红线是"签名私钥永不出仓库"。API key 是同类资产，且比签名私钥**更容易被误提交**（它会出现在配置文件而不是 `%USERPROFILE%`）。
- **成本从 0 变成正数**：当前通道边际成本 ¥0（走 IDE 里的 agent 订阅）。见 §五。
- **破坏离线优先**：刷吧定位是"独立、本地、纸笔优先"的桌面 App。

### 3.2 批改输出格式会废掉现有评分内核

方案的输出 JSON 只有 5 个字段：`result` / `triggered_errors` / `new_micro_errors` / `time_analysis` / `patch`。

而 `lib.rs:2892` 消费的是 **六维证据 + technique_level**。按方案的输出灌进去 → 六维全缺 → 按 AGENTS.md 的回退链退到「特征曲线」→ **v1.6.8 / v1.6.9 两轮评分重构的工作量直接作废**。

另外：verdict 是**四值**（`correct` / `partial` / `uncertain` / `wrong`），方案写成了三值。

### 3.3 选题提示词既没有题库视图，也没有容量约束

- 提示词里**完全没有题库信息**。5388 题不可能塞进上下文。真实做法是**先写脚本查只读快照、再挑**——这个"查询→挑选"环节方案里整体缺失。
- 没有 111′ 日容量、没有止损线、没有单叶子抽取上限。难度配比只有一句"严格控制难度梯度"（空话，没给数字）。
- 按取样策略 v5 审视，**这套提示词必然产出取样塌缩**。活例：9/1 评定的外部方案，26 题只覆盖 9 个叶子（2.9 题/叶子）。

## 四、方案的优先级算法本身有 bug（最值得说的一条）

方案 §3.3 的核心规则：

```python
error['failure_count'] += 1
if error['failure_count'] >= 3:
    error['urgency'] = 'critical'
```

**这条规则正是我 9/1 刚用倍率门槛排除掉的错误。**

`failure_count` 不区分「同一道题错 4 次」和「4 道不同的题都错」。实测反例：

| 子类 | 题次 | 不同题 | 倍率 | 正确率 | 方案会判 | 实际 |
|---|---|---|---|---|---|---|
| 泰勒多项式 | 4 | **1** | 4.00 | 25% | 🔴 **critical** | ❌ 就 #1982 一道题做了 4 次 |
| 抽象逆相关 | 7 | **7** | 1.00 | 29% | 🔴 critical | ✅ 真硬伤，样本最干净 |
| 含根式·根号加比根号减 | 7 | 4 | 1.75 | 29% | 🔴 critical | ✅ 真硬伤 |

**只看正确率排序会把泰勒多项式当成比抽象逆更严重的硬伤**——它只是同一道题重复错。

正确做法（已固化进 v5 规则 6）：

1. 全库扫描 `题次 >= 4 且 正确率 < 40%`
2. 算 **倍率 = 题次 / 不同题数**；**≥ 2.0 且不同题 ≤ 3 → 小样本，排除**
3. 剩下的才是真硬伤

> 这条我要特别标出来：**方案的优先级队列是整个方案里最有价值的部分，而它的判据是错的。**

## 七、关于 OCR（Phase 3 的"可选"项）

方案标注"可选"，但还是列进了 Phase 3。**这是降级不是升级。**

- 数学公式 OCR 准确率极低，手写草稿更差，`\frac` / 积分号 / 矩阵是重灾区
- 当前流程：拍照 → 多模态模型**直接看图**，零信息损失
- 加 OCR = 在中间插一个会丢信息的环节，而丢的恰恰是公式

**结论：不做。**

## 八、纯 agent 侧落地版（一行 App 代码都不用改）

你的约束（agent 对话为主）不但不是妥协，反而是**更优解**——它保留了单一权威源、人工可读、git 可追溯，且零成本。

### Layer 1 · 冷启动摘要（新增，≤5KB，每次会话必读）

**文件**：`E:/刷吧/characteristic-core.md`
**格式**：**markdown，不是 JSON**

为什么不用方案的 JSON：

| | JSON 方案 | markdown 方案 |
|---|---|---|
| 权威源 | md 与 JSON **双写，必然漂移** | md 唯一，JSON 不存在 |
| AI 可编辑 | 需脚本中转 | ✅ 直接改，闭环不需要脚本 |
| 人工可读 | 差 | ✅ 好 |
| 追溯 | 需 profile_snapshots 表 | ✅ **git diff 就是完整演变史**，比快照表更强 |

内容（控制在 5KB 内）：

```
当前 top 5 断点：错误码 | 触发条件 | 否定式规则 | 验收判据 | 下次验收日
王牌能力 3 条（带证据题号）
到期复习数 / 当前排产队列 P0–P5
三条硬事实（选择题无 d=2 / 44% 叶子题量≤4 / 止损线）
```

### Layer 2 · 决策日志（新增，append-only markdown）

**文件**：`E:/刷吧/考研规划/决策日志.md`

这就是方案 `ai_selection_log` 的纯文件版。方案里 `actual_results` 标注"事后填充"却没说**谁填**——文件版的答案是：**下一轮会话的 AI 回填**。

每条记录字段：

```
日期 | 场景(v5 A–I) | 我看到的关键数据 | 选了哪些题 | 预期判据 | 实际结果(下轮回填) | 结论
```

**「预期判据」必须写死在选题那一刻**——这是防自我服务偏差的关键。9/1 的教训：先选了题、做完了再看结果，会不自觉地把结果解释成"符合预期"。

### Layer 3 · 数据库（只读，不新建任何表）

已有表足够：`learning_diagnoses`（136）/ `learning_evidence`（324）/ `skill_states`（146）/ `codex_task_context`（168）。
需要复杂查询时写临时脚本查只读快照，查完即删（现有纪律）。

### 落地清单（按优先级）

| # | 动作 | 成本 | 解决什么 |
|---|---|---|---|
| 1 | 建 `characteristic-core.md`（≤5KB） | 30′ | 每次会话不必读 70KB |
| 2 | 建 `考研规划/决策日志.md` + 每轮回填 | 10′ + 每轮 2′ | 决策可追溯（方案唯一真增量） |
| 3 | 把 v5 §7 的 12 项推送前自检做成决策日志的**强制字段** | 0（已在 v5 里） | 防取样塌缩 |
| 4 | 优先级判据改用**倍率门槛**（v5 规则 6） | 0（已在 v5 里） | 修掉方案 §3.3 的 bug |

## 十、最终判定

| 维度 | 评分 | 说明 |
|---|---|---|
| 问题诊断 | ❌ 不合格 | 4 个硬事实全错，没读代码库 |
| 能力诉求 | ⚠️ 部分对 | 3 条真需求，其中 1 条（可追溯）是真增量 |
| 架构方案 | ❌ 否决 | 重复建设 + 付费替换免费 + 破坏离线优先 |
| 优先级算法 | ❌ 有 bug | `failure_count` 缺倍率门槛，已被实测证伪 |
| 成本估算 | ❌ 矛盾 | Opus 按 Sonnet 计价；总量 ¥1,080 vs 当前 ¥0 |
| **可 salvage 的部分** | ✅ **约 15%** | 决策日志 + 画像分层（改用 markdown 实现） |

**一句话**：这份方案把真问题（决策不可追溯）找对了，但开错了药方（重建管道）。
**管道本来就通，堵的是管道里流的决策规则**——那正是取样策略 v5 在补的东西。
